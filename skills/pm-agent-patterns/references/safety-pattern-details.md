## 护栏系统

### P-SAF-01 输入过滤 🔴 高风险

**问题场景**：恶意用户通过精心构造的输入进行 Prompt 注入、越狱攻击或数据窃取。

**解决方案**：对用户输入做多层级安全检查。

**实施层级**：
```
Level 1：格式检查 — 输入是否符合预期格式
Level 2：语义检查 — 是否包含已知攻击模式
Level 3：意图分析 — LLM 判断真实意图
Level 4：上下文检查 — 输入是否试图操纵系统指令
```

**已知实例**：
- Claude Code（7 层纵深防御）、OpenAI（Moderation API）、Google（Safety Settings）

**常见陷阱**：
- 过度过滤误伤正常输入——需要精确度/召回率平衡
- 过滤规则静态不变——攻击手法持续进化

### P-SAF-02 输出审查 🔴 高风险

**问题场景**：AI 生成有害、不准确或违反政策的内容。

**解决方案**：对 AI 输出进行安全审查，阻止不合格内容到达用户。

**实施方式**：
```
实时审查：输出前检查每一段内容
后处理审查：完整输出后整体评估
用户反馈：用户标记 + 人工复审
持续监控：统计分析异常输出模式
```

**已知实例**：ChatGPT（内容过滤）、Claude（Constitutional AI）

### P-SAF-03 行为边界 🟡 中风险

**问题场景**：AI 在某些领域的行为需要被严格限制（如医疗、法律、金融建议）。

**解决方案**：定义 AI 不可执行的操作类型和不可进入的话题领域。

**实施方式**：
- 话题边界：明确列出不可讨论的话题
- 操作边界：明确列出不可执行的操作
- 边界声明：在输出中明确标注"这不是专业建议"

**已知实例**：ChatGPT（医疗/法律免责声明）、Claude Code（Scope Gate）

### P-SAF-04 回退策略 🟡 中风险

**问题场景**：AI 不确定或无法完成时，不应该编造答案。

**解决方案**：定义安全回退行为——诚实说不 + 提供替代路径。

**回退层级**：
```
Level 1：直接承认"我不确定" — 最安全
Level 2：提供部分信息 + 标注不确定性 — 有条件使用
Level 3：建议替代方案 — 引导用户到正确渠道
Level 4：转移到人工 — 最完善的兜底
```

**已知实例**：Google AI（"可能不准确"标注）、客服系统（转人工）

## 权限控制

### P-SAF-05 最小权限 🔴 高风险

**问题场景**：AI 拥有超过完成当前任务所需的权限，增加了滥用风险。

**解决方案**：AI 只拥有完成任务所需的最小权限集合。

**实施原则**：
- 默认拒绝（Deny-first）
- 按需授权
- 用后即撤
- 定期审查

**已知实例**：
- Claude Code（默认只读，写入需确认）、Devin（microVM 隔离）

### P-SAF-06 分级授权 🔴 高风险

**问题场景**：不同操作的风险级别不同，应该需要不同级别的授权。

**解决方案**：按风险级别分层授权。

**授权级别**：
```
Level 0：自动允许（只读、查询）
Level 1：首次确认后记住（写入非敏感文件）
Level 2：每次确认（写入敏感文件、发送消息）
Level 3：双重确认（删除、执行命令、影响他人）
Level 4：禁止（系统级操作、安全绕过）
```

**已知实例**：
- Claude Code（7 种权限模式）、Claude（tool 权限分级）

### P-SAF-07 临时权限 🟡 中风险

**问题场景**：AI 偶尔需要高风险操作权限，但不应该永久拥有。

**解决方案**：高风险操作需用户实时授权，用后即撤。

**实施方式**：
- 请求时弹窗说明操作影响
- 用户批准后执行一次
- 执行完毕自动撤销

**已知实例**：Claude Code（AllowOnce 权限模式）

### P-SAF-08 权限审计 🟡 中风险

**问题场景**：需要追溯 AI 使用了哪些权限、做了什么操作。

**解决方案**：记录所有权限使用行为，支持审计和追溯。

**审计内容**：
- 权限请求时间、类型、原因
- 授权结果（允许/拒绝/撤销）
- 实际操作详情
- 操作结果

**已知实例**：Claude Code（hook 日志）、Devin（审计日志）

## 边界防护

### P-SAF-09 速率限制 🟡 中风险

**问题场景**：AI 操作过于频繁导致资源耗尽或成本失控。

**解决方案**：限制 AI 的操作频率。

**限制维度**：
- 每分钟/每小时操作次数
- 每日 token 消耗上限
- 并发操作数上限

### P-SAF-10 资源配额 🟡 中风险

**问题场景**：AI 消耗过多计算资源或 API 费用。

**解决方案**：为 AI 设置资源配额和预算上限。

**配额类型**：
- Token 配额（每会话/每日/每月）
- 费用配额（每日/每月费用上限）
- 时间配额（单次操作最大时长）

### P-SAF-11 沙盒隔离 🔴 高风险

**问题场景**：AI 的执行环境可能影响生产系统。

**解决方案**：AI 在隔离的沙盒环境中执行，与生产环境物理/逻辑隔离。

**隔离层级**：
```
Level 1：进程隔离 — 独立进程运行
Level 2：容器隔离 — Docker/容器化
Level 3：虚拟机隔离 — 独立 VM
Level 4：物理隔离 — 独立硬件
```

**已知实例**：
- Devin（microVM 隔离）、Claude Code（worktree 隔离）、E2B（云沙盒）

### P-SAF-12 数据边界 🔴 高风险

**问题场景**：AI 不应该访问所有数据，只应该访问与任务相关的数据。

**解决方案**：限制 AI 可访问的数据范围。

**边界类型**：
- 文件系统边界：仅允许访问项目目录
- 网络边界：仅允许访问白名单域名
- 数据库边界：仅允许查询特定表/视图
- API 边界：仅允许调用授权的 API

## 审计与追溯

### P-SAF-13 全链路日志 🟡 中风险

**问题场景**：需要完整了解 AI 从输入到输出的每一步。

**解决方案**：记录 AI 从接收输入到产生输出的完整链路。

**日志内容**：
- 输入内容（用户原始请求）
- 推理过程（Prompt 构建、工具选择）
- 工具调用（参数、返回值、耗时）
- 输出内容（最终响应）

### P-SAF-14 可解释性输出 🟡 中风险

**问题场景**：用户/审计人员需要理解 AI 为什么做出某个决策。

**解决方案**：AI 的决策过程对人类可理解。

**可解释性层级**：
```
Level 1：结果解释 — "我选择X因为Y"
Level 2：过程展示 — 可展开的推理步骤
Level 3：证据引用 — 引用具体信息来源
Level 4：替代方案 — 展示被排除的选项和原因
```

### P-SAF-15 版本控制 🟢 低风险

**问题场景**：AI 的行为发生变化，需要追踪和回滚。

**解决方案**：AI 的行为版本可追踪、可回滚。

**版本控制范围**：
- Prompt 版本
- 模型版本
- 工具集版本
- 配置版本

### P-SAF-16 影响评估 🟡 中风险

**问题场景**：AI 操作前不知道会造成什么影响。

**解决方案**：AI 操作前评估潜在影响范围。

**评估维度**：
- 影响范围（影响几个用户/文件/系统）
- 可逆性（能否撤销）
- 影响持续时间
- 级联效应（是否会触发其他操作）

## 安全模式选择决策树

```
产品类型？
│
├─ 纯对话（无操作能力）
│   └─ → P-SAF-01 + P-SAF-02 + P-SAF-03（输入输出过滤 + 行为边界）
│
├─ 辅助工具（有有限操作能力）
│   └─ → + P-SAF-05 + P-SAF-06 + P-SAF-10（权限控制 + 资源配额）
│
├─ 自主 Agent（有完全操作能力）
│   └─ → + P-SAF-07 + P-SAF-11 + P-SAF-12（临时权限 + 沙盒 + 数据边界）
│
└─ 企业级产品
    └─ → + P-SAF-08 + P-SAF-13 + P-SAF-14 + P-SAF-16（审计 + 可解释 + 影响评估）
```

## 权限模型演进路径

```
RBAC（基于角色的访问控制）
  └─ 简单产品，角色固定
      ↓ 产品复杂度增加
ABAC（基于属性的访问控制）
  └─ 中等产品，属性灵活组合
      ↓ Agent 自主性增加
IBAC（基于身份的访问控制）
  └─ 复杂产品，每个 Agent 实例独立权限
```

**参考**：Dextra Labs "Agentic AI Safety Playbook"（2025）
