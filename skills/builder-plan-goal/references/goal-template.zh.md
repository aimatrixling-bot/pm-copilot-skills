# Goal 提示词模板

当任务已有清晰结果、边界和验证方式时，使用这些模板。

## 通用结构：G-C-S-D-V-R

- Goal：最终结果。
- Context：必要上下文。
- Scope：允许做什么，不允许做什么。
- Done when：完成标准。
- Verification：验证方式。
- Reporting：最终报告要求。

## 通用模板

```text
/goal

Goal:
[最终要达成的业务/工程结果。写结果，不写愿望。]

Context:
- 背景：[为什么要做]
- 当前状态：[已有能力、已知问题、相关模块]
- 优先查看：[目录/文件/测试/日志/截图/设计稿]

Scope:
- 本次只做：[明确范围]
- 本次不做：[明确排除项]
- 允许修改：[文件/模块/层级]
- 不要修改：[公共 API、数据库 schema、权限、认证、生产配置、无关页面等]

Constraints:
- 遵循现有技术栈、架构和代码风格。
- 不引入新依赖，除非必要且说明理由。
- 保持 diff 小、可审查、可回退。

Done when:
- [可验收标准 1]
- [可验收标准 2]
- [边界/异常/回归标准]

Verification:
- 运行：[lint/typecheck/build/test/benchmark/manual QA]
- 如果无法运行，请说明原因和人工验证步骤。
- 报告精确命令、结果和剩余风险。

Working rules:
- 先阅读相关上下文，再给出简短执行计划。
- 小步实现并自查 diff。
- 不要扩大范围。
- 如果遇到阻塞性业务/安全/架构问题，停止并报告证据、尝试路径和需要用户决策的问题。

Final report:
- 改了什么
- 文件变更
- 验证结果
- 风险或假设
- 人工 review 点
- 建议下一步
```

## Bug 修复 Goal

```text
/goal

Goal:
修复 [具体 bug]，并保持现有行为不回归。

Context:
- 异常行为：[实际发生了什么]
- 期望行为：[正确行为]
- 复现步骤：
  1. [步骤 1]
  2. [步骤 2]
  3. [步骤 3]
- 已知证据：[错误日志、失败测试、截图、最近变更]

Scope:
- 做最小安全修复。
- 如可行，添加或更新回归测试。
- 不改变公共 API、数据库 schema、权限或无关流程。

Done when:
- bug 按复现步骤不再出现。
- 相关测试通过。
- 回归测试覆盖该问题，或说明为什么暂时不可行。

Verification:
- 重新执行复现步骤。
- 运行最小相关测试集。
- 如可用，运行 lint/typecheck/build。
- 报告命令、结果和剩余风险。
```

## 新功能 Goal

```text
/goal

Goal:
实现 [功能名称]，使用户可以 [用户动作]，系统可以 [系统结果]。

Context:
- 用户故事：作为 [角色]，我想 [动作]，以便 [价值]。
- 相关页面/路由/模块：[路径]
- 需要遵循的现有示例：[类似功能/组件/API]

Scope:
- 只实现 [本次范围]。
- 不实现 [未来路线图或排除项]。
- 复用现有组件、API 调用方式和状态管理模式。

Done when:
- Given [前置条件]，when [用户行为]，then [系统结果]。
- Given [异常情况]，when [用户行为]，then [错误处理]。
- loading、empty、error 状态按需处理。
- 相关测试或手工 QA 可以验证。

Verification:
- 运行相关测试。
- 运行 lint/typecheck/build。
- 提供手工 QA 步骤。
```

## UI / 原型 Goal

```text
/goal

Goal:
实现 [页面/流程名称] 的可运行 UI 原型，使业务评审者能理解 [核心流程/业务对象/决策点]。

Context:
- 参考材料：[截图/设计稿/文字描述/现有页面]
- 目标路由：[路径]
- 目标用户：[用户角色]
- 数据状态：本里程碑使用 mock 数据，除非现有项目已有真实 API。

Scope:
- 实现视觉布局、核心交互状态和响应式基础。
- 使用本地 mock 数据。
- 不做真实认证、数据库、后端集成或生产级 Agent 编排。

Done when:
- 页面可以在目标路由打开。
- 桌面端可用，移动端不出现明显布局破坏。
- 主要状态清楚：默认、空、加载、错误，如适用。
- 信息层级、间距、字体和业务表达符合目标。

Verification:
- 启动 dev server 并提供本地 URL。
- 运行 lint/typecheck/build。
- 如可用，使用浏览器截图检查主要视口。
- 报告视觉差异和假设。
```

## 重构里程碑 Goal

```text
/goal

Goal:
执行已批准重构计划中的 Milestone [编号]：[里程碑名称]。

Context:
- 已批准计划：[计划摘要或文件]
- 本里程碑目标：[具体边界]
- 不变行为：[必须保持的公共行为]

Scope:
- 只执行 Milestone [编号]。
- 保持公共 API 稳定，除非计划已明确批准。
- 不做格式化-only 或无关重构。

Done when:
- Milestone [编号] 完成。
- 用户可见行为不变。
- 相关测试通过。
- diff 可审查，且不包含后续里程碑内容。

Verification:
- 运行相关测试。
- 运行 lint/typecheck/build。
- 汇报模块边界变化和剩余里程碑。
```

## Eval / Prompt / Skill 优化 Goal

```text
/goal

Goal:
优化 [prompt/skill/eval/agent workflow]，直到 [指标或验收标准] 达成。

Context:
- 当前问题：[失败样例、低分项、用户反馈]
- 评估方式：[eval 命令、测试集、人工评审标准]
- 允许修改：[prompt、模板、测试、文档等]

Scope:
- 只改与评估目标直接相关的内容。
- 不改变无关运行时逻辑或历史基线，除非明确说明。

Done when:
- [通过率/质量标准/人工验收] 达成。
- 失败样例被解释或修复。
- 变更原因清楚，可复查。

Verification:
- 运行指定 eval 或人工检查清单。
- 报告改前/改后差异。
```
