# 场景差异化设计规则

> **原则驱动声明**：以下场景规则是"原则的具体化 + 边界锚点"，不是死规则。
> 遇到未见过的场景时，回到原则推理，而不是盲目套用最近似的场景规则。
> 原则 > 场景规则 > AI 推断。
>
> **配套参考**：原则的可执行规则详见 `executable-rules.md`（20 条经典 UX 规则，按 IA/ID/VD/DD/AG 五域分类）。

## 核心原则（遇到未知场景时回到这里）

| # | 原则名称 | 原则描述 | 适用所有场景 |
|---|----------|----------|:----------:|
| P1 | 信息密度与姿态匹配 | Sovereign 姿态 → 高密度；Transient 姿态 → 低密度 | ✅ |
| P2 | 触控目标 ≥44px（H-ID03） | 所有触控场景，鼠标场景可放宽至 28px | ✅ |
| P3 | 能用枚举不用自由文本（H-ID04） | 所有表单场景，移动端优先级最高 | ✅ |
| P4 | 状态必须颜色+文字双编码 | 所有需要状态指示的场景 | ✅ |
| P5 | 流程完整性底线 | 从入口到目标达成的完整路径，不能跳步 | ✅ |

## 场景规则矩阵（具体化的原则 + 边界锚点）

### 1.1 场景差异化矩阵（8 维度 × 6 场景）

| 维度 | B 端 Web/PC | B 端 移动端 | C 端 Web/PC | C 端 移动端 | 平板横屏 | 平板竖屏 |
|------|------------|------------|------------|------------|---------|---------|
| **信息密度** | 高：表格为主，一屏 20+ 数据字段，行高 36-40px | 中：卡片摘要+详情进入，一屏 5-8 条 | 中：图文混排，留白适度 | 低：单任务聚焦，每屏一个核心操作 | 高→中：利用宽度展示双栏/表格式数据 | 中→低：单栏流式，适当折叠 |
| **导航模式** | 持久侧边栏(200-260px) + 顶部面包屑 + Tab 切换 | 底部 Tab(3-5项) + 汉堡菜单 + 筛选栏 | 顶部导航栏 + 搜索 + Mega Menu | 底部 Tab(4-5项) + 顶部搜索 | 侧边栏(可收起) + 顶部导航 + 分屏 | 侧边栏(抽屉式) + 顶部导航 |
| **表单设计** | 多列布局(2-4列)，行内编辑，批量操作，Tab 分组 | 单列堆叠，分步向导，自动聚焦，选择>输入 | 2 列布局，浮动标签，实时验证 | 全宽单列，大输入框(≥44px)，下一步式 | 2 列布局，侧边预览，表单+详情分屏 | 单列，卡片分组，分步向导 |
| **数据展示** | 数据表格(排序/筛选/列自定义) + 汇总统计 + 图表 | 卡片列表 + 筛选栏 + 汇总头 | 网格卡片 + 轮播 + 时间线 | 信息流/卡片 + 下拉刷新 + 无限滚动 | 表格+侧边详情面板 | 卡片流+底部操作栏 |
| **交互模式** | 键盘快捷键(⌘K 等)，右键菜单，拖拽排序，批量选中 | 手势(滑动删除)，下拉刷新，底部操作栏，确认模态框 | Hover 预览，鼠标跟随，视差滚动 | 手势驱动(左滑/下拉)，大按钮(≥44px)，Toast 反馈 | 触控+键盘混合，Split View 拖拽分割 | 触控优先，按钮>手势(H-ID03) |
| **视觉风格** | Precision Enterprise / Industrial Utility：克制、系统化、低装饰 | Precision Enterprise 移动版：紧凑但可读，图标容器化 | Editorial Authority / Luxury Minimal：品牌表达、视觉叙事 | Playful Modular / Organic Natural：愉悦、直觉、沉浸 | Precision Enterprise：高密度、双栏协作 | 介于 C 端移动和 B 端 PC 之间 |
| **触控目标** | 28×28px 最小(鼠标操作为主)，可点击行 | ≥44×44px(H-ID03：医疗场景用按钮不用手势)，按钮间距 ≥8px | 32×32px 最小，图标按钮 36px | ≥44×44px，底部操作栏 48px，标签栏 56px | ≥44×44px，分屏拖拽手柄 20px 宽 | ≥44×44px，全宽按钮优先 |
| **反馈层级** | 3 级：Toast(轻)→行内消息(中)→Modal(重)；批量操作用进度条 | 2 级：Toast + Modal；操作成功用视觉反馈+微动效 | 3 级：Toast→行内→全屏反馈；动效增强感知 | 2 级：Toast + 触觉反馈(haptic)；成功页+动画 | 同 B 端 PC，增加触控反馈 | 同 C 端移动，适当增加密度 |

### 1.2 产品姿态映射

基于 About Face 的产品姿态理论，为不同场景选择姿态：

| 场景 | 产品姿态 | 设计含义 |
|------|----------|----------|
| B 端 Web/PC | **Sovereign（主权型）** | 用户长时间使用，信息密度优先，效率>学习曲线，允许复杂功能 |
| B 端 移动端 | **Transient（临时型）+ Sovereign 的子集** | 碎片化使用，只保留核心操作，快速完成单一任务 |
| C 端 Web/PC | **Sovereign 或 Transient** | 取决于产品类型（电商=Sovereign，搜索=Transient） |
| C 端 移动端 | **Transient（临时型）** | 每次使用时间短，即时满足，极简操作 |
| 平板横屏 | **Sovereign 子集** | 类似桌面但触控优先，适合内容消费+轻创作 |
| 平板竖屏 | **Transient 子集** | 类似手机但屏幕更大，适合阅读+浏览 |

## 场景规则详解

### SC-01：场景判断优先

> **原则声明**：P1+P2+P3 的组合推断。场景判断是设计规则的入口，判断错误则后续所有规则失效。

**规则**：在原型生成前，必须先判断产品场景（B 端/C 端 × PC/移动/平板），场景决定设计规则集。若用户未指定，从 PRD 或描述中推断。

**AI 推断优先级**：
1. 先检测 AI Agent 关键词（优先级最高，因为交互范式差异最大）
2. 再检测 B 端/C 端关键词
3. 再检测设备关键词
4. 都无法确定 → `auto` → 默认 B2B-PC

---

### SC-02：信息密度规则（原则 P1 的具体化）

> **原则声明**：信息密度必须与产品姿态匹配。Sovereign=高密度；Transient=低密度。

**规则**：
- B 端：行高 36-40px，字号 12-14px，间距 8-16px
- C 端：行高 48-56px，字号 14-16px，间距 16-24px

**跨行业示例**：
- 医疗 B 端 → 高密度（患者列表一屏 20+ 行，行高 36px）
- 金融 B 端 → 高密度（交易记录表格，紧凑布局）
- 电商 C 端 → 中密度（商品网格卡片，适当留白）
- 社交 C 端 → 低密度（信息流单条，大图 + 少文字）
- 教育 B 端 → 中密度（课程列表 + 进度条，平衡密度与可读性）

---

### SC-03：移动端枚举优先（原则 P3 的具体化）

> **原则声明**：能用枚举不用自由文本。移动端输入成本远高于选择成本。

**规则**：移动端表单优先使用：Select > Radio > Switch > Input。每增加一个文本输入框，移动端表单完成率下降 ~5%。

**跨行业示例**：
- 医疗移动端 → 诊断用 ICD 编码搜索（非自由输入），科室用列表选择
- 物流移动端 → 货物类型用图标网格选择（非文本），状态用 Radio
- 零售移动端 → 商品规格用 SKU 选择器（非描述输入），数量用 Stepper

---

### SC-04：表单字段必填性通用判断框架

> **原则声明**：必填性判断不是"感觉"，是系统化的五维度评估。适用于所有行业。

不从领域特定角度分类，而是从**五个通用维度**逐字段判断：

| 优先级 | 维度 | 必填条件 | 非必填条件 |
|--------|------|----------|------------|
| 1 | **系统约束** | 数据库 NOT NULL / 外键关联 | 允许 NULL 的字段 |
| 2 | **流程完整性** | 下游环节依赖（阻塞型） | 仅影响判断 / 纯辅助 |
| 3 | **合规/审计** | 监管要求 / 操作记录 | 非监管字段 |
| 4 | **数据可用性** | 空值使报表无意义 | 部分有意义 / 不影响分析 |
| 5 | **字段类型启发式** | 核心实体标识 / 状态类型 | 备注/描述/附件/标签 |

**输出格式**：必填=红色星号 `*` + `[必填]`；建议填=橙色圆点 `●` + `[建议]`；选填=`[选填]` 灰色。

**AI Prompt 规则**：生成表单时逐字段执行五维度检查，输出判断理由。用户质疑时展示各维度评分。

---

### SC-05：平板适配策略

> **原则声明**：平板是"桌面骨架+移动操作"的混合体。横屏倾向桌面，竖屏倾向手机。

**规则**：
- 平板横屏：保留侧边栏+表格等桌面结构，但所有触控目标放大到 44px
- 平板竖屏：采用移动端单栏流式布局，但利用宽度展示双列卡片

**跨行业示例**：
- 医疗平板横屏 → 患者列表+详情面板双栏，触控目标 44px
- 零售平板竖屏 → 商品卡片双列流式，底部操作栏
- 教育 iPad → 横屏做课件编辑（Sovereign），竖屏做阅读（Transient）

## 场景判断逻辑（AI 执行伪代码）

```
输入：PRD/描述 + 用户指定（可选）
  │
  ├── 用户指定场景？
  │   ├── 是 → 使用指定场景
  │   └── 否 → 从输入推断
  │         │
  │         ├── 关键词检测（优先级从高到低）：
  │         │   ├── "Agent/智能体/Copilot/AI助手/对话/Chat" → AI Agent（Chat-first）
  │         │   ├── "工作流/节点/编排/Flow/Automation" → AI Agent（Workflow-first）
  │         │   ├── "AI编程/代码生成/Code Agent" → AI Agent（Chat+Canvas）
  │         │   ├── "管理/后台/CRM/ERP/SaaS/系统" → B 端
  │         │   ├── "APP/小程序/手机/移动" → 移动端
  │         │   ├── "商城/社区/内容/消费" → C 端
  │         │   ├── "iPad/平板/大屏" → 平板
  │         │   └── 无匹配 → B 端 Web/PC（PM 工具最常见场景）
  │         │
  │         └── 输出示例：
  │             scene = {
  │               type: B2B|C2C|AI_AGENT,
  │               device: PC|Mobile|Tablet,
  │               posture: Sovereign|Transient|Collaborative,
  │               agentParadigm: Chat|Canvas|Workflow|Autonomous
  │             }
  │
  └── 必须在输出中展示推断结果和理由，用户可覆盖
```
