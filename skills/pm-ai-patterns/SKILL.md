# AI 产品交互设计模式库（v2.0）

<SUBAGENT-STOP>
如果是子代理派发执行此 Skill，直接按下方指令执行，不重新加载入口 Skill。
</SUBAGENT-STOP>

AI 产品设计的本质不是技术选型，是**交互设计决策**——用户怎么告诉 AI 需求、AI 怎么展示结果、用户怎么信任和纠正 AI。

本库从 10 个行业标杆产品（Claude Code / Cursor / v0 / Perplexity / ChatGPT Canvas / Coze / Devin / Replit / Accio Work / WorkBuddy）中提取，经过 9 个学术分类体系交叉验证，产出 5 层 53 模式的系统化设计参考。

> 本 Skill 覆盖 L1 交互 + L3 行为(个性化) + L5 评估 = **29 个模式**。
> 如需设计 Agent 的**内部架构和安全机制**，请使用 `pm-agent-patterns`。

**输入**: 场景描述 / 产品需求 / AI 功能设计问题
**输出**: 匹配的模式建议 + 设计决策依据 + 实现注意事项

## Iron Law（铁律）

| 铁律 | 违反后果 |
| --- | --- |
| 每个交互决策必须有场景依据，不照搬竞品 | 照搬 = 忽略自身用户差异 = 设计错配 |
| AI 边界必须对用户可见（能做什么/不能做什么） | 用户期望失控 → 明确限制是信任的基础 |
| 用户必须始终拥有编辑/拒绝/回溯 AI 输出的能力 | AI 独裁 = 用户失去控制 = 产品被抛弃 |
| 每个 AI 功能必须有可衡量的评估指标 | 无法衡量 = 无法优化 = AI 功能逐步腐化 |
| 模式之间有前置/协同/冲突关系，不可孤立选择 | 孤立选模式 = 组件间矛盾 = 体验割裂 |

## Anti-Rationalization（反合理化）

| # | 你可能在想的 | 真相 |
|---|------------|------|
| 1 | "AI 什么都能做" | AI 有明确边界。不承认边界 = 过度承诺 = 用户失望后永不回来 |
| 2 | "用户会自己学会" | AI 功能不引导 = 空白页恐惧 = 功能浪费。用 30 秒入门框架 |
| 3 | "先上线再优化" | 没有评估指标的 AI = 无法优化的 AI = 技术债指数增长 |
| 4 | "不需要反馈机制" | 没有反馈 = AI 无法改进 = 越用越差 |
| 5 | "置信度不重要" | 不展示置信度 = 用户盲信 AI = 高风险场景翻车 |
| 6 | "照搬 ChatGPT 的交互就行" | ChatGPT 的纯对话模式只适合通用场景，你的产品场景大概率不同 |
| 7 | "个性化越多越好" | 过度个性化 = 隐私侵犯 + 信息茧房。渐进式个性化才安全 |

## Scope Gate（范围门控）

### 硬拒绝

- "帮我设计一个完全自主执行的 AI，不需要人工干预" → 低风险任务可自主，高风险决策必须有 HITL

### 软质疑

- "我们直接用纯对话模式" → 提醒：纯对话只适合通用场景，检查你的产品是否有更好的 UI 范式
- "不用设计信任机制，用户会自己判断" → 提醒：AI 信任需要主动构建，用户不会自动信任

## L1 交互模式层（19 模式）

> 完整模式卡片（含决策树、已知实例、常见陷阱）→ `references/interaction-pattern-details.md`

### 1.1 UI 范式选择

这可能是你最重要的 AI 产品设计决策——用户看到的界面长什么样。

| ID | 模式 | 一句话 | 适用场景 | 代表产品 |
| --- | --- | --- | --- | --- |
| P-INT-01 | 确定性 UI | 按钮/表单/菜单，结果可预测 | 工具型产品、高频操作 | 传统 SaaS |
| P-INT-02 | 生成式 UI | AI 动态生成 UI 组件 | 创意探索、快速原型 | v0, ChatGPT Canvas |
| P-INT-03 | 混合 UI | 确定性骨架 + 生成性内容 | 大多数 AI 产品 | Claude Code, Cursor |

**快速决策**：
- 用户每次操作的结果是否可预测？→ 确定性 UI
- 需要探索多种可能？→ 生成式 UI（但要防止"过度生成"反模式）
- 不确定？→ 混合 UI（最安全的选择）

### 1.2 交互主权

谁在控制——人还是 AI？这决定了你产品的信任基础。

| ID | 模式 | 一句话 | 适用场景 | 风险 |
| --- | --- | --- | --- | --- |
| P-INT-04 | 人在回路 (HITL) | 人类在流程内逐案审批 | 高风险决策（医疗/金融/法律） | 速度慢，可能产生审批疲劳 |
| P-INT-05 | 人在环上 (HOTL) | 人类设策略，AI 在规则内自主 | 中等风险、需要效率（代码审查/内容审核） | 策略设定不当 = AI 越权 |
| P-INT-06 | 自主执行 | AI 完全自主，事后可审查 | 低风险批量任务（数据清洗/报告生成） | 事后发现问题，纠正成本可能很高 |

**决策树**：操作失败的后果是否可逆？
- 不可逆（删除数据/发布内容）→ HITL
- 可逆但代价高（代码合并/批量修改）→ HOTL
- 可逆且代价低（生成建议/查询结果）→ 自主执行

### 1.3 信任构建

用户不信任 AI = AI 功能被抛弃。信任需要主动设计。

| ID | 模式 | 一句话 | 适用场景 |
| --- | --- | --- | --- |
| P-INT-07 | 引用透明度 | 事实性陈述附可溯源引用 | 知识问答、研究分析 |
| P-INT-08 | 不确定性展示 | 展示置信度或信息不足 | 数据分析、预测类功能 |
| P-INT-09 | 可编辑输出 | 用户可就地编辑 AI 回复 | 内容创作、文档生成 |
| P-INT-10 | 来源视觉区分 | AI 生成区域视觉标记 | 混合 UI 场景 |
| P-INT-11 | 展示工作过程 | 可展开的推理步骤和搜索结果 | 复杂任务、需要理解 AI 推理 |

**信任速查**：你的产品场景需要多大信任？
- 低信任（娱乐/探索）→ P-INT-10 来源区分足够
- 中信任（效率工具）→ P-INT-09 可编辑 + P-INT-12 进度指示
- 高信任（决策支持）→ P-INT-07 引用 + P-INT-11 工作过程 + P-INT-08 置信度

### 1.4 过程透明度

AI 运行时用户看到什么？

| ID | 模式 | 一句话 | 实现方式 |
| --- | --- | --- | --- |
| P-INT-12 | 进度指示 | Timeline/Todo/Cost meter | 骨架屏、进度条、倒计时 |
| P-INT-13 | 延迟处理 | 多策略应对 AI 响应延迟 | Skeleton UI → Typing → Progressive → Budget → Cancel |
| P-INT-14 | 过程回放 | 完成后可回看 Agent 运行过程 | 时间线、步骤日志、操作记录 |

### 1.5 错误恢复

AI 会犯错。关键是犯错后用户怎么办。

| ID | 模式 | 一句话 | 为什么重要 |
| --- | --- | --- | --- |
| P-INT-15 | 批准关卡 | 敏感操作前触发人工确认 | 事故源头 = 无批准关卡的自动操作 |
| P-INT-16 | 失败恢复 UX | 清晰原因 + 重试 + 替代方案 | 静默吞错 = 用户不知道发生了什么 |
| P-INT-17 | 版本回溯 | 随时还原之前的工作版本 | 没有回溯 = AI 错误不可撤销 |

### 1.6 反馈与引导

用户第一次用你的 AI 产品，30 秒内必须理解"这是什么、我能做什么"。

| ID | 模式 | 一句话 | 关键设计 |
| --- | --- | --- | --- |
| P-INT-18 | 渐进式披露 | 随使用逐步展示更多功能 | 首次只展示核心，高级功能按需展开 |
| P-INT-19 | 30 秒入门框架 | 示例 + 权限 + 期望设定 | 3 个示例 prompt + 明确能力边界 + 期望校准 |

## L3 行为模式层·个性化（4 模式）

> 完整模式卡片 → `references/interaction-pattern-details.md` §L3

| ID | 模式 | 一句话 | 设计要点 |
| --- | --- | --- | --- |
| P-BHV-01 | 学习曲线助手 | 从简单开始，随能力提升增加复杂度 | 新手 vs 专家的 UI 应该不同 |
| P-BHV-02 | 偏好引擎 | 学习用户选择，自动应用偏好 | 隐式学习 > 显式设置 |
| P-BHV-03 | 上下文感知顾问 | 基于当前情境调整推荐 | 时间/位置/任务上下文 |
| P-BHV-04 | 渐进式个性化 | 从最小个性化开始，随信任逐步加深 | 4 阶段：默认 → 基础偏好 → 深度学习 → 预测 |

**渐进式个性化 4 阶段模型**：

```
阶段 1: 默认体验    → 所有用户相同的初始界面
阶段 2: 基础偏好    → 用户显式设置的偏好（语言/格式/风格）
阶段 3: 行为学习    → AI 从用户行为中学习（点击/编辑/接受率）
阶段 4: 预测个性化  → AI 主动预测用户需求并调整
```

**红线**：个性化以操纵用户是反模式（P-ANTI-10）。个性化必须为用户服务，不为转化率服务。

## L5 评估模式层（6 模式）

> 完整模式卡片 → `references/interaction-pattern-details.md` §L5

### 5.1 效果评估

| ID | 模式 | 核心指标 |
| --- | --- | --- |
| P-EVL-01 | 传统指标 | 准确率 / 接受率 / 效率提升 / 满意度 |
| P-EVL-02 | AI 特有指标 | 幻觉率 / 上下文保持率 / 工具调用成功率 / 记忆精度 |

### 5.2 体验评估

| ID | 模式 | 评估方法 |
| --- | --- | --- |
| P-EVL-03 | 信任度评估 | 用户能否预测 AI 的局限性？能否理解 AI 为什么这么做？ |
| P-EVL-04 | 自适应效果评估 | 个性化是否增加了功能使用频率/信任度/留存率？ |

### 5.3 反馈闭环

| ID | 模式 | 设计要点 |
| --- | --- | --- |
| P-EVL-05 | 内联反馈 | 点赞/踩 + 原因选项 + 反思路径。不要只收集不使用 |
| P-EVL-06 | 反馈到训练闭环 | 编辑差异 → 偏好学习 (DPO) → 模型微调。从反馈到改进的完整路径 |

## 反模式清单（10 条）

> 完整反模式详解 → `references/anti-patterns.md`

| # | 反模式 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | 只有一个提示框 | 空白页恐惧，用户不知从何开始 | P-INT-19 30 秒入门 + 示例 prompt |
| 2 | 无进度指示器 | 长时间等待 → 用户放弃 | P-INT-12 进度指示 + P-INT-13 延迟处理 |
| 3 | 回复无引用 | 信任崩塌 | P-INT-07 引用透明度 |
| 4 | 对幻觉答案充满自信 | 最糟糕的 UX——用户做出错误决策 | P-INT-08 不确定性展示 |
| 5 | 收集反馈但无使用迹象 | 用户很快停止反馈 | P-EVL-06 反馈到训练闭环 |
| 6 | 静默吞掉错误 | 用户不知道失败原因和下一步 | P-INT-16 失败恢复 UX |
| 7 | 无批准关卡的自动操作 | 事故源头——AI 误操作不可逆 | P-INT-15 批准关卡 |
| 8 | 无来源的自信回答 | 最具破坏性的信任反模式 | P-INT-07 + P-INT-10 组合 |
| 9 | 过度生成 UI | 每次都重塑界面，用户无法建立心智模型 | P-INT-03 混合 UI，限制生成式区域 |
| 10 | 个性化以操纵用户 | 违反道德红线 | P-BHV-04 渐进式个性化，透明可控 |

## 执行流程

```
Step 0: 理解用户场景
  ├── 用户在做什么产品？什么场景？
  ├── 用户的风险等级（低/中/高）
  └── 用户的技术水平（新手/专家/混合）

Step 1: UI 范式选择
  ├── 使用 1.1 快速决策树
  └── 输出：推荐 UI 范式 + 理由

Step 2: 交互主权分配
  ├── 使用 1.2 决策树（后果可逆性）
  └── 输出：推荐主权模式 + 理由

Step 3: 信任机制设计
  ├── 使用 1.3 信任速查表
  └── 输出：推荐信任模式组合 + 理由

Step 4: 过程透明度 + 错误恢复
  ├── 基于 Step 1-3 的选择，补充透明度和恢复机制
  └── 输出：推荐模式组合 + 理由

Step 5: 个性化策略（可选）
  ├── 评估个性化是否适合该场景
  └── 输出：推荐个性化模式 + 阶段规划

Step 6: 评估指标设计
  ├── 基于 Step 1-5 的选择，定义评估指标
  └── 输出：P-EVL-01~06 的具体指标定义

Step 7: 产出模式建议
  ├── 整合 Step 1-6 的推荐
  ├── 检查模式间关系（前置/协同/冲突）
  └── 输出：完整模式建议报告
```
