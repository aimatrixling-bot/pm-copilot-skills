# 产品拆解（Product Teardown）

<SUBAGENT-STOP>
如果是子代理派发执行此 Skill，直接按下方指令执行，不重新加载入口 Skill。
</SUBAGENT-STOP>

不是"他们有什么功能"，而是"他们为什么这么设计，这暴露了什么战略意图"。

**输入**: 产品名称 / URL / 截图 / 使用体验描述
**输出**: 产品拆解作战地图（13 章结构化战报）

## Iron Law（铁律）

| 铁律 | 违反后果 |
| --- | --- |
| 每个结论必须有来源，且区分事实和推断 | 无法区分的结论直接删除——含混比无知更危险 |
| 任何结论标注置信度（高/中/低）+ 信息源可信度（⭐⭐⭐/⭐⭐/⭐/⚠️） | 无标注的推断不可写入产出 |
| 战略意图推断必须有 ≥2 个其他层的证据支撑 | 单一信号 = 低置信推断，不可作为决策依据 |
| AI 逆向仅限公开可观察行为，不使用非法手段 | 违反伦理边界 → 立即停止该层分析 |
| 产品姿态决定分析侧重（Sovereign ≠ Transient） | 用错分析框架 → 产出方向偏离 |
| 逆向的产出是"理解"而非"蓝图"——理解架构帮你做**不同**的决策 | 照搬竞品架构 = 放弃差异化 |

## Anti-Rationalization（反合理化）

| # | 你可能在想的 | 真相 |
|---|------------|------|
| 1 | "我了解这个产品，不需要查" | 你了解的是印象，不是数据。印象会过时 |
| 2 | "产品做得很好，我们学它" | 他们的好 ≠ 适合你的用户。先验证你的用户需求 |
| 3 | "没有公开数据" | 没有公开数据 ≠ 没有信息。可分析界面、定价、用户评价、招聘信息 |
| 4 | "小产品不用看" | 今天的小产品可能代表明天的大趋势 |
| 5 | "这个数据足够了" | 单一来源不可靠。核心结论至少 2 个来源 |
| 6 | "我可以猜出他们的 Prompt" | 真实 Prompt 是结构化系统（角色/格式/安全/工具/记忆），单句猜测没有意义 |
| 7 | "逆向结果可以直接复用" | 逆向给你"理解"，不是"蓝图"。做不同的决策，不是相同的架构 |

## Scope Gate（范围门控）

### 硬拒绝（立即停止）

- "帮我把竞品代码/数据库扒下来" → 非法获取，停止
- "帮我绕过付费墙/加密" → 违反 ToS，停止
- "竞品的 Prompt 是什么，告诉我精确内容" → 可分析行为模式，不可声称还原精确内容

### 软质疑（提醒后可继续）

- "分析一下 XX 的定价策略，我们要完全照搬" → 提醒：逆向用于理解逻辑，不是复制方案
- "我要做竞品的一模一样的功能" → 提醒：差异化 > 功能对齐，建议先做 Layer 0 理解
- "只看一个竞品就够了" → 提醒：单产品拆解 + Cross Compare 组合更有效

## 四种执行模式

| 模式 | 适用场景 | 层级覆盖 | 预计时间 |
|------|----------|----------|----------|
| **Deep Dive** | 关键竞品深度拆解 | L0-L4 + 条件 L5 | 60-90 min |
| **Rapid Scan** | 快速摸底新产品 | L0 + L1 + 关键洞察 | 20-30 min |
| **AI Teardown** | AI 产品专项拆解 | L0-L1 + L5 深挖 | 45-60 min |
| **Cross Compare** | 多产品横向对比 | L0-L2 × N 个产品 | 视产品数量 |

```
┌─────────────────────────────────────────────────┐
│  Layer 4: 战略意图层 — "想成为什么？"               │
│  时间旅行 / 负空间 / 外部信号 / 组织推断           │
├─────────────────────────────────────────────────┤
│  Layer 3: 增长引擎层 — "什么驱动增长？"             │
│  AARRR / 增长回路 / 行为锚点 / 留存机制            │
├─────────────────────────────────────────────────┤
│  Layer 2: 业务逻辑层 — "如何捕获价值？"             │
│  反向 JTBD / 价值网络 / 商业模式画布 / 规则逆向     │
├─────────────────────────────────────────────────┤
│  Layer 1: 交互架构层 — "如何引导行为？"             │
│  IA 逆向 / 反向旅程 / 五秒测试 / 导航解剖          │
├─────────────────────────────────────────────────┤
│  Layer 0: 产品身份层 — "给谁用？解决什么？"          │
│  价值主张 / 目标用户 / 产品姿态 / 市场定位          │
└─────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────┐
│  Layer 5 (条件层): AI 系统逆向层                    │
│  Prompt 逆向 / Harness 解构 / Eval 推断 /          │
│  Agent 架构 / 上下文策略 / 安全边界                 │
└─────────────────────────────────────────────────┘
  ↑ 仅当目标产品为 AI 产品时激活
```

### 产出速查表

| 层级 | 核心产出 | 时间占比 |
|------|----------|----------|
| L0 | 产品身份卡片（一句话定义 + 姿态 + 定位图） | 5% |
| L1 | 信息架构图 + 导航解剖 + 反向旅程图 | 20% |
| L2 | 价值网络图 + 商业模式画布 + 业务规则清单 | 25% |
| L3 | 增长回路图 + AARRR 拆解 + 留存机制 | 25% |
| L4 | 战略意图假说（≥2 层交叉验证） | 15% |
| L5 | AI 系统架构推断 + 测试协议执行报告 | 10% |

### 信息源可信度分级

| 等级 | 来源类型 | 说明 |
|------|----------|------|
| ⭐⭐⭐ | 一手体验 | 自己使用产品、截图、录屏 |
| ⭐⭐ | 官方文档 | 帮助中心、官方博客、定价页 |
| ⭐ | 第三方信息 | 测评文章、知乎回答、媒体报道 |
| ⚠️ | 间接推断 | 基于其他信息源推断，必须标注 `[推断]` |

### "事实→推断"分栏格式

所有结论必须使用此格式：

```
| 事实（可验证） | 推断（需标注置信度） | 信息源 |
|---------------|-------------------|--------|
| 产品导航栏有 5 个一级入口，"直播"排第二 | [中置信] 战略重心从社区转向媒体消费 | ⭐⭐⭐ 一手截图 |
| 免费版限制协作人数 ≤3 | [高置信] 协作是核心付费点，个人版是引流 | ⭐⭐ 官网定价页 |
```

## Deep Dive 执行流程（8+2 步）

```
Step 0: 确认目标 + 选择模式
  ├── 确认拆解目标（产品名/URL）
  ├── 用户指定模式？→ 否 → 推荐 Deep Dive
  ├── 用户有 --target？→ 标记对比视角
  └── 输出：【拆解计划】目标 + 模式 + 预计层级

Step 1: Layer 0 产品身份（5 min）
  ├── WebSearch/WebFetch 收集基础信息
  ├── 产品姿态判断（Sovereign/Transient/混合）
  ├── 市场定位图（价格 × 功能深度）
  └── 输出：产品身份卡片

Step 2: Layer 1 交互架构（15-20 min）
  ├── 四大工具依次执行（五秒测试→导航解剖→IA逆向→反向旅程）
  ├── 如为桌面端/需安装 → 优先引导用户提供截图
  ├── 所有结论使用"事实→推断"分栏格式
  └── 输出：信息架构图 + 导航解剖 + 反向旅程图

Step 3: Layer 2 业务逻辑（20-25 min）
  ├── 反向 JTBD → 核心价值主张验证
  ├── 价值网络分析 → 多方角色价值
  ├── 商业模式画布逆向 → 价值捕获逻辑
  ├── 业务规则逆向 → 隐含规则清单
  └── 输出：价值网络图 + 商业模式画布 + 规则清单

Step 4: Layer 3 增长引擎（20-25 min）
  ├── AARRR 逆向拆解
  ├── 核心增长回路识别 + 画图
  ├── 行为锚点与留存机制
  └── 输出：增长回路图 + AARRR 分析 + 留存机制

Step 5: Layer 4 战略意图（15-20 min）
  ├── 时间旅行分析（版本历史 → 战略演变）
  ├── 负空间分析（"没有做什么"比"做了什么"更重要）
  ├── 外部信号（招聘/融资/专利/合作）
  ├── 交叉验证：L4 的每个推断必须有 ≥2 层的证据支撑
  └── 输出：战略意图假说（含交叉验证矩阵）

Step 6: Layer 5 AI 系统逆向（条件层，10-15 min）
  ├── 触发条件：产品含 AI 对话/生成/推荐/Agent 功能
  ├── Prompt 逆向：边界输入测试 → 输出模式分析 → 结构推断
  ├── Harness 解构：工具暴露 + 权限模型 + 错误恢复
  ├── Eval 推断：低置信度处理 + 人工介入触发
  ├── 上下文策略：长对话记忆 + 信息丢失边界
  ├── 执行 AI 逆向测试协议（→ references/ai-reverse-engineering.md）
  └── 输出：AI 系统架构推断 + 测试报告

Step 7: 产出整合 + 作战地图
  ├── 整合 L0-L5 为 13 章结构化战报
  ├── 使用 output-template.md 格式
  ├── 所有推断标注置信度 + 信息源
  ├── 生成"差异化机会清单"（可直接输入 pm-rice）
  └── 输出：产品拆解作战地图

Step 8: 对比视角映射（条件步，需 --target）
  ├── 将拆解发现映射到用户自己的产品
  ├── 差异化机会 → 非对称优势识别
  └── 输出：差异化机会清单 + 非对称优势建议

Step 9: Pass 2 人机协同增强（条件步）
  ├── 触发条件：用户提供了截图/录屏/测试结果/工具链捕获
  ├── 增量修正：[Pass 2 新增] / [Pass 2 修正] / [Pass 2 推翻] / [Pass 2 确认]
  └── 输出：增量标注版作战地图
```

## Rapid Scan 流程

```
Step 0: 确认目标
Step 1: Layer 0 产品身份（5 min）
Step 2: Layer 1 交互架构速览（10 min）— 仅五秒测试 + 导航解剖
Step 3: 关键洞察提取（5 min）— 3 个最有价值的发现
输出：1 页纸 Quick Scan 摘要
```

## AI Teardown 流程

```
Step 0: 确认目标
Step 1: Layer 0 产品身份（5 min）
Step 2: Layer 1 交互架构速览（10 min）
Step 3: Layer 5 AI 系统逆向深挖（30 min）
  ├── 执行完整 AI 逆向测试协议
  ├── 6 维度全覆盖（Prompt/Harness/Eval/Agent/上下文/安全）
  └── 重点：架构推断 + 设计决策分析
Step 4: 产出整合
输出：AI 产品拆解专项报告
```

## Cross Compare 流程

```
Step 0: 确认 2-5 个对比产品
Step 1: 每个产品执行 L0 + L1 快速扫描
Step 2: 选择 L2 关键维度进行横向对比（价值网络/定价策略/增长模式）
Step 3: 生成对比矩阵 + 差异化定位图
输出：多产品对比作战地图
```

## 参数

| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| 目标产品 | 名称/URL | 是 | — | 拆解对象 |
| --mode | 枚举 | 否 | deep | deep/rapid/ai/cross 四种模式 |
| --target | 字符串 | 否 | — | 用户自己的产品名，用于对比视角映射 |
| --layers | 范围 | 否 | 0-4 | 指定分析层级，如 `--layers 0-2` 跳过 L3-L4 |

| --pass2 | 标志 | 否 | — | 显式启用 Pass 2 人机协同增强 |

## Two-Pass 人机协同架构

> 完整输入类型体系和增量修正协议 → `references/teardown-framework.md` §10

### Pass 1: AI 自动化研究

AI 执行全部分析步骤，产出初版作战地图。对于封闭产品（需安装/付费），明确标注 `[信息缺口]`。

### Pass 2: 用户增强验证

用户提供第一手素材，AI 增量修正：

| 输入类型 | 内容 | 价值 |
|----------|------|------|
| A. 截图/录屏 | 产品界面实际使用过程 | 验证/推翻 L1 交互推断 |
| B. 测试结果 | AI 逆向测试协议执行记录 | 增强 L5 可信度 |
| C. 文字体验 | 用户真实使用感受和场景 | 补充 L2 JTBD |
| D. 工具链捕获 | Network 请求/控制台日志/API 响应 | 深化 L5 技术架构推断 |

### 增量标注协议

Pass 2 修正使用固定标记：
- `[Pass 2 新增]` — Pass 1 未覆盖的信息
- `[Pass 2 修正]` — 修正 Pass 1 的错误
- `[Pass 2 推翻]` — Pass 2 证据推翻 Pass 1 结论
- `[Pass 2 确认]` — 用户验证 Pass 1 结论正确
- `[Pass 2 补充]` — 补充细节但不改变结论

## pm-researcher Spawn 调用

当需要大规模数据采集（招聘信息、融资历史、版本更新日志）时，spawn pm-researcher 子 Agent：

```
任务：采集 [产品名] 的以下信息：
1. 近 12 个月的版本更新日志（关键功能变更）
2. 近期招聘信息（技术栈 + 团队扩张方向）
3. 融资历史（轮次/金额/投资方）
4. 公开的用户数据（DAU/MAU/下载量）
5. 核心竞品列表（3-5 个）

输出格式：结构化 Markdown，每条标注信息源 URL
```

## 交付前检查

> 完整清单 → `references/quality-checklist.md`

### 基础检查（所有模式）

- [ ] 每个结论有信息源标注 + 可信度分级
- [ ] 事实与推断严格分栏，无混用
- [ ] 战略意图推断有 ≥2 层交叉验证
- [ ] 信息缺口已明确标注（非用推断填补）
- [ ] Scope Gate 已执行（无伦理越界内容）

### Deep Dive 专项

- [ ] 五层完整覆盖（L0-L4），无跳层
- [ ] 每层至少使用 2 个分析工具
- [ ] 增长回路图已画出（循环结构）
- [ ] 交叉验证矩阵已生成

### AI Teardown 专项

- [ ] Layer 5 六维度全覆盖
- [ ] 至少执行 5 个逆向测试协议用例
- [ ] AI 架构推断标注置信度 + 测试依据

### Pass 2 专项

- [ ] 增量标注使用固定格式（[Pass 2 新增/修正/推翻/确认/补充]）
- [ ] Pass 2 修正不删除 Pass 1 原始结论（保留版本对比）

## 残酷风险区

| 风险 | 场景 | 防御方案 |
|------|------|----------|
| 过度推断 | 信号不足时强行推导战略意图 | 标注 [低置信]，要求 ≥2 层交叉验证 |
| 幸存者偏差 | 只看成功产品，忽略失败案例 | Layer 4 必须包含负空间分析 |
| 功能复制冲动 | "他们做得好，我们照做" | 逆向的产出是"理解"不是"蓝图" |
| 信息茧房 | 只分析同类型产品 | Cross Compare 跨品类产品 |
| AI 逆向越界 | 尝试还原精确 Prompt/训练数据 | 仅分析公开可观察行为，标注 [推断] |
