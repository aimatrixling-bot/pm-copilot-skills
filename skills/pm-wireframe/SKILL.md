## Layer 0：设计原则四问（必须先回答，再画线框）

> **为什么有这一层**：场景规则告诉 AI"做什么"，原则告诉 AI"为什么"。
> 遇到未知场景时，AI 能根据原则推理，而不是瞎猜。
> 参考：研究报告第 8.0 节（原则驱动为主，场景驱动为辅）

生成任何线框之前，依次回答四个问题，**在输出中展示回答**，不得跳过：

| # | 问题 | 答案格式 | 作用 |
|---|------|----------|------|
| Q1 | **Purpose（目的）**：这个页面/流程让用户完成什么核心任务？ | 一句话："让用户完成 X，而不需要 Y" | 防止功能蔓延，所有线框元素必须服务此目的 |
| Q2 | **Tone（语调）**：用户带着什么情绪来到这个页面？ | 从列表选一：焦虑/急迫/随意浏览/专注任务/困惑 | 决定信息密度和交互节奏（焦虑→极简；专注→高密度） |
| Q3 | **Constraints（约束）**：有什么硬性限制？ | 列出 2-5 条：设备限制/合规要求/数据限制/用户能力限制 | 约束优先于美学，线框必须体现约束 |
| Q4 | **Differentiation（差异点）**：与竞品/现有方案的最大区别是什么？ | 一句话："别人做 X，我们做 Y" | 确保线框有记忆点，不是 generic 线框 |

**输出格式示例**：

```
【Layer 0 设计原则】
Q1 Purpose：让医生在 30 秒内完成患者影像报告审核，不需要切换系统
Q2 Tone：专注任务（冷静、高效，不容干扰）
Q3 Constraints：键盘操作优先（无鼠标场景）；屏幕只读（无编辑）；符合医疗合规审计
Q4 Differentiation：竞品按时间排序，我们按风险等级排序 + 一键标记异常

→ 基于以上原则，开始生成线框。
```

**AI Prompt 规则**：
- 如果用户输入已包含这 4 个信息，直接使用
- 如果缺失，主动向用户询问（每次最多问 1 个问题，避免一次性问 4 个）
- 如果加 `--principles-confirmed` 参数，跳过本层，直接使用 Layer 0 默认值（从 PRD 提取）

# 低保真线框图

<SUBAGENT-STOP>
如果是子代理派发执行此 Skill，直接按下方指令执行，不重新加载入口 Skill。
</SUBAGENT-STOP>

从 PRD/功能描述快速生成低保真线框图。线框不是设计，是沟通工具——5 分钟内从想法到可见结构。

**输入**: PRD 文件路径或页面描述
**输出**: 低保真线框图（HTML 或 ASCII）+ 用户流程图

## 与 prototype 的区别

| 维度 | wireframe (本 Skill) | pm-prototype |
| --- | --- | --- |
| 输出 | ASCII/灰度 HTML | 可交互 HTML + CSS + JS |
| 制作时间 | ~5 分钟 | ~30 分钟 |
| 用途 | 团队内部快速对齐结构 | 用户测试、外部演示 |
| 保真度 | 低保真结构图 | 中保真可交互 |
| 可点击 | 否 | 是 |

**选择规则**: 先 wireframe 对齐结构 → 再 prototype 做交互演示。

## Iron Law

| 铁律 | 违反后果 |
| --- | --- |
| 线框不包含视觉设计 | 如果有颜色/字体/图标 → 降级为设计稿，重新做线框 |
| 每个页面必须有目的声明 | 立即停止——补充"这个页面让用户完成什么"后继续 |
| 流程完整性 | 从入口到目标达成的完整路径，不能跳步 |
| **原则先于场景规则** | 如果场景规则与 Layer 0 原则冲突 → 以原则为准，记录冲突原因 |

## 执行流程

```
Phase 0: Layer 0 设计原则四问（不可跳过）
  ├── 回答 Q1-Q4（Purpose/Tone/Constraints/Differentiation）
  ├── 向用户展示回答，获得确认（或快速确认）
  └── 输出：【Layer 0 设计原则】摘要

Phase 1: 场景判断
  ├── 用户指定 scene 参数？→ 是 → 使用指定
  └── 否 → 从 PRD/描述推断（关键词检测 → 输出 scene + 理由）

Phase 2: 方向预览（反馈节点 🔄）
  ├── 输出：场景选择 + 产品姿态 + 信息密度级别 + 导航模式（文字描述，非线框）
  ├── 用户反馈：确认 / 修改场景 / 修改姿态
  └── 🔄 可跳过（加 --no-preview 参数），但首次使用建议不跳过

Phase 3: 输入分析 + IA 提取
  ├── Read PRD 或接收页面描述
  ├── 提取关键屏幕和导航关系
  └── （如启用 IA Analysis Mode）执行卡片分类 + 导航结构

Phase 4: 用户流程定义
  ├── 定义流程：入口 → 屏幕1 → 屏幕2 → 目标
  └── 检查流程完整性（从入口到目标，无跳步）

Phase 5: 线框生成（逐屏幕）
  ├── 每个屏幕前展示：【Layer 0 原则】+ 场景规则要点（1-2 行）
  ├── 绘制布局（header/nav/main/sidebar/footer）
  ├── 标注组件（[按钮] [列表] [表单] [图片]）
  ├── 标注交互（点击跳转、弹窗说明）
  └── 考虑状态（正常/空/加载/错误）

Phase 6: 线框预览（反馈节点 🔄）
  ├── 输出：所有屏幕的 ASCII 或 HTML 线框（完整展示）
  ├── 用户反馈：调整布局 / 增删屏幕 / 修改交互标注
  └── 🔄 可跳过（加 --no-preview 参数）

Phase 7: 交付
  ├── 写入线框文件
  ├── 附加：【Layer 0 原则】摘要 + 场景适配说明
  └── 推荐下一步 Skill（pm-prototype / pm-prd）
```

**关键设计**：
- Phase 0（原则四问）和 Phase 2（方向预览）是 Layer 0 前置环节
- Phase 6（线框预览）是反馈节点
- 两个反馈节点均可跳过，但有默认快速确认（用户 10 秒未响应 → 自动继续）
- 首次使用时，Phase 0 和 Phase 2 均不可跳过（除非显式传递 `--principles-confirmed --no-preview`）

### IA Analysis Mode（信息架构优先）

当用户关注信息组织、导航结构、内容分类时启用此模式：

1. **内容盘点** — 列出所有需要组织的内容/功能
2. **卡片分类** — 建议开放式或封闭式分类方法（见 `references/ia-analysis-guide.md`）
3. **导航结构** — 输出站点地图（Max 3 层）
4. **内容模型** — 定义内容类型和关系
5. **验证方法** — 建议树状测试或首次点击测试

## 参数

| 参数 | 类型 | 必需 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 输入源 | PRD路径/文本 | 是 | — | PRD 文件或自然语言描述 |
| 输出格式 | ascii/html | 否 | html | 线框输出格式 |
| 页面列表 | 文本 | 否 | 从 PRD User Stories 提取 | 指定要生成的页面 |
| **scene** | **枚举字符串** | **否** | **auto-detect** | **B2B-PC / B2B-Mobile / C2C-PC / C2C-Mobile / Tablet-Landscape / Tablet-Portrait / AI-Agent-Chat / AI-Agent-Workflow / AI-Agent-Canvas / auto** |
| **principles-confirmed** | **布尔** | **否** | **false** | **true = 跳过 Layer 0 原则四问（用户已确认原则）** |
| **--no-preview** | **标志** | **否** | **（未设置）** | **设置后跳过 Phase 2 和 Phase 6 的反馈节点** |

### scene 参数推断规则（AI 自动执行，用户可覆盖）

| scene 值 | 推断关键词 | 线框特征 |
|----------|-------------|----------|
| `B2B-PC` | 管理/后台/CRM/ERP/SaaS/系统 | 侧边栏 + 数据表格 + 高密度 |
| `B2B-Mobile` | APP/小程序/手机/移动 + 管理 | 底部 Tab + 卡片列表 + compact |
| `C2C-PC` | 商城/社区/内容/消费（非管理） | 顶部导航 + 网格卡片 + 中密度 |
| `C2C-Mobile` | APP/小程序 + 消费 | 底部 Tab + 信息流 + 低密度 |
| `Tablet-Landscape` | iPad/平板 + 横屏 | 侧边栏（可收起）+ 双栏 |
| `Tablet-Portrait` | iPad/平板 + 竖屏 | 抽屉式侧边 + 单栏 |
| `AI-Agent-Chat` | Agent/智能体/Copilot/对话/Chat | 对话气泡 + 输入框 + 上下文标签 |
| `AI-Agent-Workflow` | 工作流/节点/编排/Flow | 画布 + 节点 + 属性面板 |
| `AI-Agent-Canvas` | AI编程/代码生成/Chat+Preview | 双栏（对话+预览）|
| `auto` | （无关键词或无法确定） | 默认 `B2B-PC`，并在输出中标注 `[auto-detected]` |

**AI 推断优先级**：
1. 先检测 AI Agent 关键词（优先级最高，因为交互范式差异最大）
2. 再检测 B 端/C 端关键词
3. 再检测设备关键词
4. 都无法确定 → `auto` → 默认 `B2B-PC`
5. **必须在输出中展示推断结果和理由**，用户可覆盖

## 线框标准

> **原则声明**：线框的核心是"结构清晰，而非美观"。场景规则是原则的具体化，不是死规则。

### 通用标准（所有场景）

- 灰度配色（#333/#666/#999/#eee），无品牌色
- 组件占位（`[按钮]` `[列表]` `[表单]` `[图片]`）
- 交互标注（点击跳转路径、弹窗触发说明）
- 响应式断点标注（如适用）

### 场景差异化标准

#### B 端 PC（scene=B2B-PC）

| 要素 | 标准 |
|------|------|
| 布局 | 侧边栏(200-260px) + 主内容区；数据列表用表格而非卡片 |
| 信息密度 | 高：一屏 ≥20 数据字段；行高 36-40px |
| 必选标注 | 必填字段：`[标签]*`；建议填：`[标签]?`；选填：`[标签]~` |
| 批量操作 | 必须标注复选框 + 批量操作栏 |
| 筛选器 | 必须标注（位于表格上方，横排） |

#### B 端移动端（scene=B2B-Mobile）

| 要素 | 标准 |
|------|------|
| 布局 | 底部 Tab(3-5项) + 内容区；列表用卡片摘要 + 点击进入详情 |
| 信息密度 | 中：一屏 5-8 条；行高 48-56px |
| 表单 | 单列堆叠；优先 `[选择]` 而非 `[输入框]`（H-ID04） |
| 按钮 | 全宽；`[按钮]` 占位符 ≥44px |

#### C 端 PC（scene=C2C-PC）

| 要素 | 标准 |
|------|------|
| 布局 | 顶部导航 + Hero区 + 内容网格 + Footer |
| 信息密度 | 中：图文混排，留白适度 |
| CTA | 必须标注（Hero区 + 每个内容块至少 1 个） |
| 社交证明 | 必须标注（评价/评分/用户数） |

#### C 端移动端（scene=C2C-Mobile）

| 要素 | 标准 |
|------|------|
| 布局 | 底部 Tab(4-5项) + 单任务流 |
| 信息密度 | 低：每屏一个核心操作 |
| 手势 | 可标注滑动操作（`[左滑删除]` `[下拉刷新]`） |
| 按钮 | 全宽；≥44px |

#### 平板横屏（scene=Tablet-Landscape）

| 要素 | 标准 |
|------|------|
| 布局 | 侧边栏（可收起）+ 双栏内容 |
| 信息密度 | 高→中：利用宽度展示表格式数据 |

#### 平板竖屏（scene=Tablet-Portrait）

| 要素 | 标准 |
|------|------|
| 布局 | 抽屉式侧边 + 单栏流式 |
| 信息密度 | 中→低：适当折叠 |

#### AI Agent 对话式（scene=AI-Agent-Chat）

| 要素 | 标准 |
|------|------|
| 布局 | 对话历史（上）+ 输入框（下）；可标注上下文标签 |
| 特殊要素 | `[建议操作]` `[引用来源]` `[产物预览]` |
| 自主权指示 | 标注当前模式：`[建议模式]` `[确认模式]` `[执行模式]` |

#### AI Agent 工作流（scene=AI-Agent-Workflow）

| 要素 | 标准 |
|------|------|
| 布局 | 画布区 + 属性面板（右侧或下方） |
| 特殊要素 | `[节点]` `[连线]` `[调试面板]` `[小地图]` |
| 状态标注 | 每个节点标注：待执行/执行中/完成/失败 |

## 每个屏幕包含

| 维度 | 内容 |
| --- | --- |
| Purpose | 这个屏幕让用户完成什么 |
| Layout | ASCII/HTML 布局表示 |
| Content | 每个区域的元素描述 |
| Components | UI 组件列表（按钮/表单/列表等） |
| Interactions | 触发和结果 |
| States | 正常/空/加载/错误 |
| Transitions | 到其他屏幕的导航方式 |

## 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 过早关注美观 | 偏离线框目的 | 只用文字和简单形状 |
| 过多细节 | 低保真变高保真 | 保持抽象 |
| 忽略流程 | 单屏视角 | 先画流程再画单屏 |
| 跳过状态 | 只考虑正常 | 考虑空/加载/错误 |
| 没有标注交互 | 不知道怎么用 | 每个可点击元素标注去向 |
| **跳过 Layer 0 原则四问** | AI 盲目套用场景规则，不适应未知场景 | **必须先回答 Q1-Q4，展示后再画线框** |
| **场景规则与原则冲突未处理** | 产出不符合真实需求 | 以 Layer 0 原则为准，记录冲突原因 |

## 交付前检查

### Layer 0 检查

- [ ] Layer 0 设计原则四问已回答并展示
- [ ] 原则与场景规则无冲突（如有冲突，以原则为准并记录）

### 场景适配检查

- [ ] 场景（scene）已判断并展示理由
- [ ] 线框要素符合场景差异化标准（见上节）
- [ ] 必填/选填标注符合五维度框架（SC-04）

### 原有检查（保留并增强）

- [ ] 每个页面有目的声明（Purpose）
- [ ] 用户流程完整（入口到目标）
- [ ] 页面间导航关系已标注
- [ ] 所有关键状态已考虑（正常/空/加载/错误）
- [ ] 组件用占位符（非真实内容）
- [ ] 无视觉设计（无颜色/字体/图标）
- [ ] 支持响应式标注（如适用）
