## 身份系统

### P-ARC-01 System Prompt 定义

**问题场景**：AI 需要明确的角色定义和能力边界，否则行为不可预测。

**解决方案**：用结构化指令定义 AI 的角色、能力边界和输出格式。

**决策树**：
```
Prompt 复杂度？
├─ 简单产品（单一功能）→ 简短角色描述 + 输出格式
├─ 中等产品（多功能）→ 角色描述 + 能力边界 + 格式要求 + 安全规则
└─ 复杂产品（Agent 系统）→ 多层 Prompt（系统层 + 任务层 + 工具层 + 安全层）
```

**已知实例**：
- ChatGPT（简洁系统 Prompt）、Claude Code（9 层 98.4%基础设施哲学）、Coze（三层 Prompt：角色/任务/工具）

**常见陷阱**：
- Prompt 过长导致"注意力稀释"——关键指令被淹没
- 角色定义模糊导致行为不一致——具体化胜过抽象化

### P-ARC-02 多角色切换

**问题场景**：同一产品需要 AI 扮演不同专业角色（如客服 + 技术支持）。

**解决方案**：在统一架构内支持角色切换，每个角色有独立的 Prompt 和能力集。

**决策树**：
```
角色切换频率？
├─ 低频（用户手动选择）→ 角色菜单 + 独立 Prompt
├─ 中频（根据场景推荐）→ 场景检测 + 角色推荐
└─ 高频（对话中动态切换）→ P-ARC-04 上下文角色推断
```

**已知实例**：Coze（多 Bot）、ChatGPT（Custom GPTs）

### P-ARC-03 自定义人格

**问题场景**：用户或品牌需要 AI 有特定的性格和风格。

**解决方案**：允许用户/品牌自定义 AI 的语言风格、专业偏向和交互方式。

**决策树**：
```
自定义深度？
├─ 表层（语言风格）→ Prompt 中的风格指令
├─ 中层（专业偏向）→ + 专属知识库 + 专业 Prompt
└─ 深层（完全人格）→ + 自定义记忆 + 独特工具集 + 行为规则
```

**已知实例**：ChatGPT Custom GPTs、Character.AI、Claude Code（CLAUDE.md 自定义）

### P-ARC-04 上下文角色推断

**问题场景**：用户不想手动切换角色，期望 AI 自动理解上下文。

**解决方案**：AI 根据对话内容、用户行为和环境上下文自动推断角色。

**已知实例**：Claude Code（根据文件类型调整行为）、Cursor（根据代码上下文调整建议）

## 记忆系统

### P-ARC-05 短期对话记忆

**问题场景**：AI 需要在当前会话内保持上下文连贯。

**解决方案**：维护当前会话的对话历史，作为上下文传递给模型。

**决策树**：
```
对话长度预期？
├─ 短对话（<10 轮）→ 简单历史窗口
├─ 中等对话（10-50 轮）→ 滑动窗口 + 重要信息提取
└─ 长对话（>50 轮）→ 需要配合 P-ARC-10/11/12
```

**已知实例**：所有对话式 AI 的基础能力

### P-ARC-06 长期用户画像

**问题场景**：跨会话记住用户偏好，让 AI "越用越懂你"。

**解决方案**：持久化存储用户的偏好、历史行为和个性化设置。

**决策树**：
```
记忆类型？
├─ 显式偏好（用户设置的）→ 配置文件/设置面板
├─ 隐式偏好（从行为推断的）→ 行为分析 + 自动提取
└─ 混合 → 显式为主 + 隐式补充
```

**已知实例**：ChatGPT（Memory 功能）、Claude Code（CLAUDE.md + MEMORY.md）、Coze（变量+状态）

**常见陷阱**：
- 记忆过期——用户偏好已变但系统还用旧记忆
- 记忆过多——噪声影响当前决策

### P-ARC-07 结构化知识库

**问题场景**：AI 需要访问产品专有知识（公司文档、产品信息、技术文档）。

**解决方案**：通过 RAG / 向量数据库 / 知识图谱注入外部知识。

**决策树**：
```
知识特征？
├─ 结构化数据（FAQ/SOP）→ 精确匹配 + 模板回复
├─ 半结构化（文档/手册）→ RAG（向量检索 + 上下文注入）
└─ 非结构化（网页/对话）→ 知识图谱 + 实体关系提取
```

**已知实例**：Perplexity（5 阶段 RAG 管道）、NotebookLM（多源知识整合）、Coze（知识库 RAG）

**常见陷阱**：
- RAG 不是万能——知识质量 > 检索算法
- 检索结果过多稀释上下文——精排比粗排更重要

### P-ARC-08 混合记忆架构

**问题场景**：产品同时需要短期对话连贯、长期用户个性化和专业知识访问。

**解决方案**：三层融合——短期对话记忆 + 长期用户画像 + 结构化知识库。

**已知实例**：ChatGPT（对话 + Memory + 浏览）、Claude Code（对话 + CLAUDE.md + 文件系统）

## 上下文管理

### P-ARC-09 滑动窗口

**解决方案**：固定 token 数的上下文窗口，超出则裁剪最早的内容。

**适用**：MVP、简单对话场景。

**已知实例**：大多数 AI 聊天产品的基础实现

### P-ARC-10 重要性评分

**解决方案**：对上下文中的信息按重要性评分，裁剪时保留高分信息。

**适用**：信息密度不均匀的场景（如混合了闲聊和关键指令的对话）。

### P-ARC-11 摘要压缩

**解决方案**：将历史对话压缩为摘要保留，而非保留原文。

**适用**：长对话场景（客服、教育、写作）。

**已知实例**：Claude Code（5 层压缩管道）

### P-ARC-12 分层上下文

**解决方案**：系统级 / 会话级 / 任务级上下文分层管理，按优先级分配 token。

**适用**：多任务或复杂工作流场景。

**已知实例**：Claude Code（系统 CLAUDE.md + 会话上下文 + 任务文件）

## 工具调用

### P-ARC-13 单工具调用

**解决方案**：一次推理调用一个工具，结果返回后继续推理。

**适用**：工具间无依赖、简单查询。

### P-ARC-14 工具链编排

**解决方案**：按顺序调用多个工具，前一个的输出是后一个的输入。

**适用**：任务有明确的步骤依赖（如：搜索 → 提取 → 格式化 → 输出）。

**已知实例**：Claude Code（Tool pool 5 步组装）、Coze（工作流编排）

### P-ARC-15 并行工具调用

**解决方案**：同时调用多个独立工具，合并结果后继续。

**适用**：工具间无依赖且需要降低延迟。

**已知实例**：Claude（parallel tool use）

## 多 Agent 协作

### P-ARC-16 编排者模式

**解决方案**：一个中心 Agent 接收用户请求，协调多个专业 Agent 执行。

**适用**：需要统一入口和多专业能力。

**已知实例**：Devin（Manager Agent）、Microsoft（Router Pattern）

### P-ARC-17 对等协作

**解决方案**：多个 Agent 平等协作，通过消息传递协调。

**适用**：Agent 间无明确层级关系。

**已知实例**：Microsoft（Mesh Pattern）

### P-ARC-18 层级委托

**解决方案**：上级 Agent 将任务委托给下级 Agent，下级完成后汇报。

**适用**：任务有明确的分解层级。

**已知实例**：Microsoft（Hierarchical Pattern）、Replit（多 Agent 角色分工）

## 执行控制

### P-ARC-19 单次执行

**解决方案**：一次用户请求 → 一次 AI 响应，无循环。

**适用**：简单查询/生成场景。

### P-ARC-20 循环执行

**解决方案**：AI 自主循环（ReAct 模式），直到任务完成或达到限制。

**适用**：复杂任务（编码/研究/调试）需要多步推理。

**已知实例**：Claude Code（ReAct while-loop）、Cursor（长时间运行循环）、Replit Agent（迭代循环）

### P-ARC-21 人工在环

**解决方案**：AI 执行到关键节点暂停等待人类确认。

**适用**：高风险操作或需要人类判断的场景。

**已知实例**：Claude Code（权限确认）、Cursor（代码审查门控）

## 模式关系矩阵

```
身份系统 ←→ 记忆系统：身份定义决定记忆结构
记忆系统 ←→ 上下文管理：记忆是上下文的持久化层
上下文管理 → 工具调用：上下文决定工具选择和参数
工具调用 ←→ 多Agent协作：工具可以是一个Agent
多Agent协作 → 执行控制：协作模式决定执行流程
执行控制 ←→ 身份系统：执行权限由身份定义
```
