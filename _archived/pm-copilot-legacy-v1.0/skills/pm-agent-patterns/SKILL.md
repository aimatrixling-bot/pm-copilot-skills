# AI Agent 架构与安全模式

<SUBAGENT-STOP>

从"它能做什么"到"它该被允许做什么"——AI Agent 产品的架构安全工程。

**输入**: 产品名称 / 场景描述 / 架构草图 / 安全需求
**输出**: 架构模式匹配报告 + 安全设计清单 + 决策树

## Iron Law（铁律）

| 铁律 | 违反后果 |
| --- | --- |
| 每个模式必须有 ≥2 个真实产品验证实例 | 无验证的模式标注为 [未验证]，不可作为决策依据 |
| 安全模式是必选项不是可选项——每个 Agent 产品必须评估 L4 全部 16 模式 | 跳过安全评估 = 上线后出事 |
| 架构决策必须明确写出 trade-off（选了什么 + 放弃了什么） | 隐含 trade-off 会在规模化时暴露 |
| 概念自然架构（5 核心概念）是起点不是终点——按需裁剪，但必须说明裁剪理由 | 盲目删减核心概念 = 技术债 |
| 不为"灵活性"过度设计——用 YAGNI 原则，当前不需要的概念不实现 | 过度工程拖慢交付速度 |

## Anti-Rationalization（反合理化）

| # | 你可能在想的 | 真相 |
|---|------------|------|
| 1 | "我的产品不是 Agent，不需要这个 skill" | 任何有 AI 对话/生成/推荐功能的产品都在做 Agent 架构决策，只是你没意识到 |
| 2 | "安全护栏会限制 AI 能力" | 护栏定义了可接受的边界，让 AI 在边界内更自信。无护栏 = 不确定行为 |
| 3 | "先用最简单的架构，以后再重构" | 核心 5 概念（身份/记忆/用户/工具/权限）后期加的成本是初期的 5-10x |
| 4 | "大厂这么做，我们也这么做" | 大厂的约束（规模/监管/团队）和你不同。理解为什么，不是照搬什么 |
| 5 | "多 Agent 一定比单 Agent 好" | 多 Agent 的协调成本常常超过收益。先用单 Agent，瓶颈出现时再拆分 |
| 6 | "RAG 能解决所有知识问题" | RAG 是工具不是架构。问题不对（知识 vs 推理 vs 执行）→ RAG 也救不了 |
| 7 | "权限系统太复杂，先不做" | 每个无权限的 AI 操作都是潜在的事故。MVP 至少需要基础权限 |

## Scope Gate（范围门控）

### 硬拒绝（立即停止）

- "帮我绕过 AI 产品的安全限制" → 安全模式是防御性的，不帮攻击
- "帮我设计一个不受监管的 AI 系统" → 合规是底线
- "这个安全模式太麻烦，跳过" → 每个安全模式至少需要评估（可以决定"暂不实施"但必须记录原因）

### 软质疑（提醒后可继续）

- "直接用最复杂的架构" → 提醒：YAGNI 原则，按需递进
- "只需要架构不需要安全" → 提醒：L4 安全评估是本 skill 的核心产出之一
- "照搬 ChatGPT 的架构" → 提醒：理解架构决策的 why，不是 copy what

### 概念裁剪决策表

| 产品阶段 | 必须实现 | 建议实现 | 可暂缓 | 理由 |
|----------|----------|----------|--------|------|
| MVP 验证 | Identity + Tools | User | Memory, Permissions | 先跑通核心流程 |

## L2 架构模式（21 模式 × 6 类）

> 完整模式卡片（问题场景→解决方案→决策树→已知实例→常见陷阱）→ `references/architecture-pattern-details.md`

### 身份系统（4 模式）

| ID | 模式名 | 一句话 | 决策信号 |
|---|--------|--------|----------|
| P-ARC-01 | System Prompt 定义 | 用结构化指令定义 AI 的角色、能力边界和输出格式 | 所有 AI 产品都需要——区别在于复杂度 |
| P-ARC-02 | 多角色切换 | 同一产品内 AI 扮演不同专业角色 | 用户需要在"专家模式"和"通用模式"间切换 |
| P-ARC-03 | 自定义人格 | 用户可以定义 AI 的性格/风格/专长 | 2C 产品或需要品牌差异化的场景 |
| P-ARC-04 | 上下文角色推断 | AI 根据对话上下文自动推断应该扮演的角色 | 角色切换太频繁、用户不愿手动选择 |

### 记忆系统（4 模式）

| ID | 模式名 | 一句话 | 决策信号 |
|---|--------|--------|----------|
| P-ARC-05 | 短期对话记忆 | 当前会话内保持上下文连贯 | 所有对话式 AI 的基础——问题是"多短" |
| P-ARC-06 | 长期用户画像 | 跨会话记住用户偏好和历史 | 产品需要"越用越好用"体验 |
| P-ARC-07 | 结构化知识库 | RAG / 向量数据库 / 知识图谱注入外部知识 | AI 需要访问产品专有知识 |
| P-ARC-08 | 混合记忆架构 | 短期 + 长期 + 知识库三层融合 | 产品有复杂知识需求且需要个性化 |

### 上下文管理（4 模式）

| ID | 模式名 | 一句话 | 决策信号 |
|---|--------|--------|----------|
| P-ARC-09 | 滑动窗口 | 固定 token 数的上下文窗口 | 最简单方案，适合 MVP |
| P-ARC-10 | 重要性评分 | 按信息重要性动态裁剪上下文 | 信息密度不均匀（有些对话关键，有些不是） |
| P-ARC-11 | 摘要压缩 | 将历史对话压缩为摘要保留 | 长对话场景（客服/教育/写作） |
| P-ARC-12 | 分层上下文 | 系统级 / 会话级 / 任务级上下文分层管理 | 多任务或复杂工作流场景 |

### 工具调用（3 模式）

| ID | 模式名 | 一句话 | 决策信号 |
|---|--------|--------|----------|
| P-ARC-13 | 单工具调用 | AI 在一次推理中调用一个工具 | 工具间无依赖、简单查询场景 |
| P-ARC-14 | 工具链编排 | AI 按顺序调用多个工具完成复杂任务 | 任务有明确的步骤依赖 |
| P-ARC-15 | 并行工具调用 | AI 同时调用多个独立工具提升效率 | 工具间无依赖且需要降低延迟 |

### 多 Agent 协作（3 模式）

| ID | 模式名 | 一句话 | 决策信号 |
|---|--------|--------|----------|
| P-ARC-16 | 编排者模式 | 一个中心 Agent 协调多个专业 Agent | 需要统一入口和多专业能力 |
| P-ARC-17 | 对等协作 | 多个 Agent 平等协作，无中心 | Agent 间无明确层级关系 |
| P-ARC-18 | 层级委托 | 上级 Agent 将任务委托给下级 Agent | 任务有明确的分解层级 |

### 执行控制（3 模式）

| ID | 模式名 | 一句话 | 决策信号 |
|---|--------|--------|----------|
| P-ARC-19 | 单次执行 | 一次用户请求 → 一次 AI 响应 | 简单查询/生成场景 |
| P-ARC-20 | 循环执行 | AI 自主循环直到任务完成或达到限制 | 复杂任务（编码/研究/调试）需要多步 |
| P-ARC-21 | 人工在环 | AI 执行到关键节点暂停等待人类确认 | 高风险操作或需要人类判断的场景 |

## L3 自主行为模式（6 模式）

> 这些模式来自 L3 层的"自主行为"子类，与 pm-ai-patterns 中的"个性化行为"互补

| ID | 模式名 | 一句话 | 自主度 | 适用场景 |
|---|--------|--------|--------|----------|
| P-BHV-07 | 自主规划 | AI 将复杂任务分解为可执行步骤 | 高 | 用户给目标不给步骤 |
| P-BHV-08 | 自我修正 | AI 检测自己的错误并自主修正 | 高 | 长链推理容易出错 |
| P-BHV-09 | 主动提问 | AI 在信息不足时主动向用户提问 | 中 | 需求模糊、信息缺失 |
| P-BHV-10 | 渐进式披露 | AI 根据用户熟练度逐步展示高级功能 | 低 | 新手/专家用户混合 |
| P-BHV-11 | 后台执行 | AI 在后台执行长任务，用户无需等待 | 高 | 任务耗时 > 30 秒 |
| P-BHV-12 | 状态持久化 | AI 记住任务进度，支持中断恢复 | 中 | 多会话工作流 |

## L4 安全模式（16 模式 × 4 类）

> 完整模式卡片 → `references/safety-pattern-details.md`

### 护栏系统（4 模式）

| ID | 模式名 | 风险等级 | 一句话 |
|---|--------|----------|--------|
| P-SAF-01 | 输入过滤 | 🔴 高 | 对用户输入做安全检查，阻止注入/越狱 |
| P-SAF-02 | 输出审查 | 🔴 高 | 对 AI 输出做安全检查，阻止有害/不准确内容 |
| P-SAF-03 | 行为边界 | 🟡 中 | 定义 AI 不可执行的操作类型 |
| P-SAF-04 | 回退策略 | 🟡 中 | AI 不确定时的安全回退行为 |

### 权限控制（4 模式）

| ID | 模式名 | 风险等级 | 一句话 |
|---|--------|----------|--------|
| P-SAF-05 | 最小权限 | 🔴 高 | AI 只拥有完成任务所需的最小权限 |
| P-SAF-06 | 分级授权 | 🔴 高 | 不同风险级别的操作需要不同级别的授权 |
| P-SAF-07 | 临时权限 | 🟡 中 | 高风险操作需用户实时授权，用后即撤 |
| P-SAF-08 | 权限审计 | 🟡 中 | 记录所有权限使用行为，支持追溯 |

### 边界防护（4 模式）

| ID | 模式名 | 风险等级 | 一句话 |
|---|--------|----------|--------|
| P-SAF-09 | 速率限制 | 🟡 中 | 限制 AI 的操作频率，防止失控 |
| P-SAF-10 | 资源配额 | 🟡 中 | 限制 AI 的资源消耗（token/时间/费用） |
| P-SAF-11 | 沙盒隔离 | 🔴 高 | AI 的执行环境与生产环境隔离 |
| P-SAF-12 | 数据边界 | 🔴 高 | 限制 AI 可访问的数据范围 |

### 审计与追溯（4 模式）

| ID | 模式名 | 风险等级 | 一句话 |
|---|--------|----------|--------|
| P-SAF-13 | 全链路日志 | 🟡 中 | 记录 AI 从输入到输出的完整链路 |
| P-SAF-14 | 可解释性输出 | 🟡 中 | AI 的决策过程对人类可理解 |
| P-SAF-15 | 版本控制 | 🟢 低 | AI 的行为版本可追踪、可回滚 |
| P-SAF-16 | 影响评估 | 🟡 中 | AI 操作前评估潜在影响范围 |

## 设计决策速查

```
问题：我的产品需要什么架构？
│
├─ 产品有对话功能？→ 至少需要 P-ARC-01 + P-ARC-05 + P-ARC-09
├─ 产品需要"记住用户"？→ + P-ARC-06 + P-ARC-10
├─ 产品需要外部知识？→ + P-ARC-07 或 P-ARC-08
├─ 产品有复杂工作流？→ + P-ARC-14 + P-ARC-12
├─ 需要多专业能力？→ 考虑 P-ARC-16 或 P-ARC-18（先验证单 Agent 瓶颈）
│
├─ 产品会执行操作（非纯对话）？→ 必须评估 P-SAF-01 到 P-SAF-16
├─ 操作涉及用户数据？→ P-SAF-05 + P-SAF-12 是必须的
├─ 操作涉及资金/交易？→ P-SAF-06 + P-SAF-07 + P-SAF-11 是必须的
└─ 面向企业客户？→ P-SAF-08 + P-SAF-13 + P-SAF-14 是必须的
```

## 执行流程（6 步）

```
Step 0: 确认场景
  ├── 用户提供了产品/场景描述？→ 提取关键需求
  ├── 用户提供了架构草图？→ 评估现有设计
  └── 输出：【分析范围】产品类型 + 关键需求 + 分析层级

Step 1: 概念映射（5 min）
  ├── 对照"概念自然架构"5 核心概念
  ├── 判断产品阶段（MVP/PMF/规模化）
  ├── 确定哪些概念必须/建议/可暂缓
  └── 输出：概念映射表 + 裁剪决策

Step 2: 架构模式匹配（15-20 min）
  ├── L2 21 模式逐个评估（至少覆盖相关子类）
  ├── 每个模式标注：适用 / 不适用 / 待定
  ├── 适用的模式给出实现优先级
  └── 输出：架构模式匹配表 + 优先级排序

Step 3: 自主行为评估（10 min）
  ├── 评估产品需要的自主度（高/中/低）
  ├── 匹配 L3 自主行为模式
  ├── 确定人机协作边界
  └── 输出：自主度评估 + 人机协作设计

Step 4: 安全评估（15-20 min）
  ├── L4 16 模式逐个评估
  ├── 每个模式标注：必须 / 建议 / 暂缓 + 理由
  ├── 标注风险等级和实现复杂度
  └── 输出：安全评估清单 + 实施路线图

Step 5: 架构决策总结（10 min）
  ├── 整合 Step 1-4 产出
  ├── 明确 trade-off（选了什么 + 放弃了什么）
  ├── 生成架构决策记录（ADR 格式）
  └── 输出：架构决策文档 + 实施路线图
```

## 交付前检查

## 与 pm-ai-patterns 的关系

| 维度 | pm-ai-patterns | pm-agent-patterns (本 skill) |
|------|----------------|------------------------------|
| 覆盖层 | L1 交互 + L3 个性化 + L5 评估 | L2 架构 + L3 自主行为 + L4 安全 |

## Capability Index

| 维度 | CAN（可以做） | CANNOT → HANDOFF（不做，转交） |
|---|---|---|
