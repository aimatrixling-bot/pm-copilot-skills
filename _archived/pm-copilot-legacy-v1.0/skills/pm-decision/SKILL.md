# 决策支持

<SUBAGENT-STOP>
如果是子代理派发执行此 Skill，直接按下方指令执行，不重新加载入口 Skill。
</SUBAGENT-STOP>

帮助 PM 做出有依据的产品决策——从"我觉得应该选 A"到"基于 X 证据和 Y 约束，A 方案在 Z 条件下更优"。

**核心原则**：好决策不是选对的，是知道为什么选。决策框架的价值在于让选择可追溯、可复盘、可质疑。

## Intent Packet

| 字段 | 捕获内容 | 来源 |
|---|---|---|
| **Want** | 在多个方案间做出有依据的产品决策，输出可追溯的决策记录 | 用户输入剥离"帮我决定"后的任务本质 |
| **Constraints** | 每个方案必须有 ≥ 1 个劣势、所有假设必须标注、必须 ≥ 2 个方案 | Iron Law |
| **Context Sources** | 决策问题 + 已有方案 + 约束条件 + `references/decision-frameworks.md` + `references/pricing-framework.md`（定价决策） | 用户提供 + Read |
| **Depth** | Quick（≤ 2 问 + 加权矩阵 + 建议）/ Expert（含假设反转/时间轴/二阶效应/不可逆性评估，默认） | 用户声明（Entry Mode）或推断 |
| **Output Target** | 决策者本人 + 决策记录归档（团队复盘可追溯） | 用户明示或推断 |

未提供时标注 `[假设]`，交付前确认。

## Iron Law（铁律）

| 铁律 | 违反后果 |
| --- | --- |
| 不列出劣势的方案分析无效 | 立即停止——补充每个方案的 ≥ 1 个劣势后继续 |
| 没有假设的决策不可信 | 立即停止——标注所有隐含假设后继续 |
| 只有一个方案的决策不是决策 | 立即停止——生成 ≥ 1 个替代方案后继续 |

## 反合理化

| 你可能在想的 | 真相 |
| --- | --- |
| "用户已经知道要选什么" | 知道选择 ≠ 理解为什么选。决策记录的价值在于"为什么" |
| "这个方案明显更好" | "明显"是偏见。用数据或逻辑证明，不用直觉 |
| "两个方案差不多，随便选" | 差不多 = 决策风险低 ≠ 不需要记录。记录下来，下次不用重新想 |
| "老板说了选 A" | 老板的决策也需要记录依据，否则无法复盘 |
| "时间紧迫，快速选一个" | 快速选可以，但不能跳过记录。10 分钟的决策记录省 10 小时的返工 |

## Capability Index

| 维度 | CAN（可以做） | CANNOT → HANDOFF（不做，转交） |
|---|---|---|
| **任务类型** | 方案选择（加权矩阵）、方向决策（假设映射）、权衡决策（Trade-off 曲线）、Go/No-Go（一页纸）、定价策略 | 优先级排序 → pm-prioritize（RICE/ICE）；商业战略方向 → pm-strategy-session；技术选型 → pm-code-architect |
| **输出格式** | 标准决策记录 Markdown（含 Decision Statement/方案分析/评估矩阵/推荐/假设/验证） | 决策树图表 → 可视化工具；演示文稿 → pptx |
| **深度范围** | 单次处理 1 个决策问题；从 Quick（≤ 2 问）到 Expert（含二阶效应/不可逆性） | 多决策联动/长期战略决策 → pm-strategy-session；决策执行跟踪 → 项目管理工具 |

**边界原则**：决策记录的价值在"为什么"，不在"选了什么"。即使方案明显更优，也要记录依据，否则无法复盘。

## Entry Mode

### Quick（快速模式）— ≤ 2 个问题后直接产出

**问题 1**: "你要做什么决策？有哪些方案？"
**问题 2**（可选）: "有什么约束或偏好？"

然后：
- 自动生成 ≥ 2 个方案（如果用户只给 1 个，自动生成 1 个替代）
- 对每个方案列出优势/劣势/风险
- 用加权决策矩阵评分
- 给出建议 + 理由
- 标注所有 [假设]

### Expert（专家模式）— 直接产出 + 高级选项

**高级选项**:
- A. 加权决策矩阵 — 多维度加权评分
- B. 假设反转 — "如果关键假设错了，结论会变吗？"
- C. 时间轴分析 — "6 个月后，哪个方案更优？"
- D. 二阶效应 — "选 A 之后，会引发什么新问题？"
- E. 定价决策 — 使用定价策略框架（见 `references/pricing-framework.md`）

**产出增强**:
- 决策矩阵表格
- 假设清单（带置信度）
- 最小可行验证建议
- 不可逆性评估（可逆决策快速做，不可逆决策慎重做）

## 决策框架

根据决策类型自动选择框架：

| 决策类型 | 框架 | 适用场景 |
| --- | --- | --- |
| 方案选择 | **加权决策矩阵** | A vs B vs C，多维度比较 |
| 优先级决策 | **RICE / ICE** | 先做什么后做什么（路由到 pm-prioritize） |
| 方向决策 | **假设映射** | "如果 X 为真则选 A，如果 Y 为真则选 B" |
| 权衡决策 | **Trade-off 曲线** | 速度 vs 质量、短期 vs 长期 |
| Go/No-Go | **一页纸决策** | 做 vs 不做，列出支持/反对 |
| 定价策略 | **定价框架** | 价值定价 vs 成本加成 vs 竞争定价 + 定价心理学 |

详细框架模板见 `references/decision-frameworks.md`。

## 执行流程

```
触发 pm-decision
    ├── 1. 解析决策问题
    │     ├── 决策类型（方案选择/优先级/方向/权衡/Go-No-Go）
    │     ├── 已有方案列表
    │     └── 约束条件
    ├── 2. 自动选择框架
    ├── 3. 分析方案（优势 + 劣势 + 风险）
    │     └── 标注 [假设] 和置信度
    ├── 4. Iron Law 检查
    │     ├── 每个方案有劣势？
    │     ├── 所有假设已标注？
    │     └── ≥ 2 个方案？
    ├── 5. 产出建议 + 最小可行验证
    └── 6. 交付 + 写入决策记录
```

## 交付前检查

- [ ] ≥ 2 个方案被分析
- [ ] 每个方案有 ≥ 1 个优势和 ≥ 1 个劣势
- [ ] 所有假设已标注 [假设]
- [ ] 关键假设有置信度评估
- [ ] 有明确的推荐 + 理由
- [ ] 有最小可行验证建议
- [ ] 决策记录使用标准格式
- [ ] **推荐方案的执行路径无 Magic Step**
- [ ] **Trade-off 中的技术约束经过验证**（不是假设可行）

## Meta-Review

交付完成后对照方法论自审：

1. **方法论骨架**：是否遵循 解析决策 → 选框架 → 分析方案 → Iron Law 检查 → 建议+验证 → 写入记录 的完整流程？
2. **反理实化警惕**：5 条"你可能在想的"（用户已知/明显更好/差不多随便选/老板说了/时间紧迫）是否真的被警惕了？
3. **Iron Law 验证**：3 条铁律是否已验证满足（每方案有劣势、所有假设标注、≥ 2 个方案）？

自审结果 1-2 句话附在交付物末尾。不通过时回到对应步骤修正。

## Evolution Writeback

执行后自问以下 3 个问题，有则记录到 `docs/evolution-log.md`：

1. **方法论偏差**：决策框架（加权矩阵/假设映射/Trade-off/Go-No-Go/定价）是否不够贴合实际场景？
2. **反理实化补充**：是否发现新的"决策乐观主义"借口模式？
3. **边界调整信号**：CAN/CANNOT 边界是否需要调整（如某类决策频繁被转交到 pm-strategy-session）？

记录格式：`## YYYY-MM-DD — pm-decision — [决策类型/场景]`
