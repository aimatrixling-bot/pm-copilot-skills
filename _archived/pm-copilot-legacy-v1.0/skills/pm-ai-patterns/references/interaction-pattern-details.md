## 输入模式

### P-INT-01 自然语言输入

**问题场景**：用户想用自己熟悉的方式表达需求，不想学特定语法。

**解决方案**：接受自然语言描述作为输入，AI 负责理解意图。

**决策树**：
```
用户技术能力？
├─ 非技术人员 → 自然语言输入（必须）
├─ 一般用户 → 自然语言 + 可选结构化引导
└─ 技术人员 → 自然语言 + 支持精确语法/代码输入
```

**已知实例**：ChatGPT（纯对话）、Perplexity（搜索查询）、v0（UI 描述）

**常见陷阱**：
- 自然语言输入的歧义性——需要确认机制
- 过度依赖用户表达能力——提供示例和引导

### P-INT-02 结构化表单输入

**问题场景**：用户需要提供明确的参数，减少歧义。

**解决方案**：用表单/模板引导用户填写结构化输入。

**决策树**：
```
输入参数类型？
├─ 选项有限 → 下拉选择/单选
├─ 需要精确值 → 文本框 + 校验
└─ 复杂结构 → 分步表单 + 即时预览
```

**已知实例**：Coze Bot 配置、Midjourney 参数、Notion AI 模板

**常见陷阱**：
- 表单过于复杂吓跑用户——渐进式披露
- 限制了创意表达——表单 + 自然语言混合

### P-INT-03 多模态输入

**问题场景**：用户想用图片/文件/语音等方式表达需求。

**解决方案**：支持多种输入模态的混合使用。

**决策树**：
```
需要表达的复杂度？
├─ 简单查询 → 文本足够
├─ 涉及视觉内容 → + 图片输入
└─ 涉及文档处理 → + 文件上传
```

**已知实例**：ChatGPT（图片+文件）、Claude（图片+PDF）、v0（设计稿参考）

**常见陷阱**：
- 多模态理解不完美——需要确认
- 文件大小/格式限制——明确提示

### P-INT-04 上下文感知输入

**问题场景**：用户已经在某个工作上下文中，不想重复描述。

**解决方案**：AI 自动感知用户的当前上下文（选中内容、打开文件、浏览历史）。

**决策树**：
```
上下文可获取性？
├─ IDE/编辑器环境 → 自动读取选中代码/文件
├─ 浏览器环境 → 读取页面内容/选中文字
└─ 通用环境 → 提供手动附加上下文的方式
```

**已知实例**：Claude Code（CLAUDE.md + 文件上下文）、Cursor（代码库理解）、GitHub Copilot（当前文件）

**常见陷阱**：
- 隐私风险——自动读取敏感内容
- 上下文过多导致噪声——智能过滤

## 输出模式

### P-INT-05 直接输出

**问题场景**：用户只需要答案，不需要过程。

**解决方案**：AI 直接给出最终结果。

**已知实例**：Perplexity（搜索答案）、Google AI Overviews

### P-INT-06 流式输出

**问题场景**：等待时间长会影响用户体验。

**解决方案**：逐 token 展示 AI 的生成过程。

**已知实例**：所有主流 AI 聊天产品

### P-INT-07 可编辑输出

**问题场景**：AI 输出不完全符合预期，用户想微调。

**解决方案**：输出内容可就地编辑、删除或重新生成。

**已知实例**：ChatGPT Canvas、Notion AI、Cursor inline edit

### P-INT-08 结构化输出

**问题场景**：输出需要被下游系统消费，或需要特定格式。

**解决方案**：AI 输出 JSON/表格/代码等结构化格式。

**已知实例**：Claude（JSON mode）、Coze（API 输出）、代码生成工具

## 过程透明模式

### P-INT-09 展示工作过程

**问题场景**：用户不信任"黑箱"输出，需要看到推理过程。

**解决方案**：可展开的推理步骤、搜索结果、工具调用记录。

**已知实例**：Perplexity（引用链）、Claude（extended thinking）、Devin（执行日志）

### P-INT-10 引用透明度

**问题场景**：用户需要验证 AI 输出的事实准确性。

**解决方案**：每条事实性陈述附可溯源引用链接。

**已知实例**：Perplexity（编号内联引用，平均 21.87 个/回答）、Google AI Overviews

### P-INT-11 不确定性展示

**问题场景**：AI 不确定时不应该假装确定。

**解决方案**：展示置信度、标注信息不足、提供多个可能答案。

**已知实例**：Google AI（"可能不准确"标注）、医疗 AI（置信度评分）

### P-INT-12 来源视觉区分

**问题场景**：用户需要区分哪些是 AI 生成的、哪些是原始内容。

**解决方案**：AI 生成区域用图标、背景色或边框标记。

**已知实例**：Notion AI（紫色标记）、Google Docs AI（高亮）

## 人机协作模式

### P-INT-13 人在回路（HITL）

**问题场景**：AI 需要在关键决策点暂停等待人类确认。

**解决方案**：敏感操作前触发确认弹窗，人类决策权威。

**已知实例**：Claude Code（权限确认）、Cursor（代码审查门控）、Coze（边界优先）

### P-INT-14 人在环上（HOTL）

**问题场景**：AI 自主执行，人类在旁监督可随时介入。

**解决方案**：AI 自主运行，人类可随时中断或调整。

**已知实例**：Devin（人类指导-Agent 执行）、Replit Agent（实时监督中断）

### P-INT-15 渐进信任轨迹

**问题场景**：初次使用时不应该给 AI 完全自主权。

**解决方案**：信任从低到高递进——首次确认 → 习惯后自动 → 可回退。

**已知实例**：Claude Code（7 种权限模式）、macOS（隐私权限渐进授权）

## 错误恢复模式

### P-INT-16 版本回溯

**问题场景**：AI 做错了，用户想回退到之前的状态。

**解决方案**：支持随时还原之前的工作版本。

**已知实例**：ChatGPT Canvas（版本回溯）、Devin（时间旅行回退）

### P-INT-17 重新生成/修正

**问题场景**：输出方向对但细节需要调整。

**解决方案**：提供"重新生成"、"微调"、"换个方向"等操作。

**已知实例**：ChatGPT（重新生成按钮）、Midjourney（variation）

## 上下文感知模式

### P-INT-18 智能触发

**问题场景**：用户不应该需要手动调出 AI。

**解决方案**：AI 根据上下文自动判断何时介入。

**已知实例**：GitHub Copilot（自动补全）、ChatGPT Canvas（智能切换编辑模式）

### P-INT-19 场景化提问模板

**问题场景**：用户不知道怎么提问才能获得最佳结果。

**解决方案**：根据当前场景提供预设的问题模板。

**已知实例**：NotebookLM（场景化提问建议）、Coze（Prompt 模板库）

## 模式关系图

```
输入模式 ──→ 过程透明 ──→ 输出模式
   │              │              │
   │              ▼              │
   │         人机协作 ◄─────────┘
   │              │
   ▼              ▼
错误恢复 ◄── 上下文感知

关系类型：
- 顺序依赖：输入 → 过程 → 输出
- 互补：过程透明 + 人机协作 = 可信的 AI
- 增强：上下文感知增强所有模式的效果
- 兜底：错误恢复是所有模式的最后一道防线
```
