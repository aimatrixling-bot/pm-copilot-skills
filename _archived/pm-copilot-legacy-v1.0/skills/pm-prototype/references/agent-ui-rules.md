# AI Agent 界面设计规则

> **适用场景**：当 pm-prototype 的 `scene` 参数为 `AI-Agent-Chat`、`AI-Agent-Workflow`、`AI-Agent-Canvas` 时，本文件规则优先于通用规则。
> **原则依据**：基于 AI UX Playground（172 模式）、Agentic Design（21 模式）、WorkBuddy/Cursor/Claude 等产品的实践提炼。

---

## AI Agent 界面设计矩阵（4 范式 × 10 维度）

| 维度 | AI 对话助手 | AI 编程 Agent | AI 工作流编排 | AI 自主执行 Agent |
|------|------------|-------------|-------------|-----------------|
| **交互范式** | Chat-first | Chat+Canvas | Workflow-first | Chat+监控面板 |
| **信息密度** | 中（对话流+引用） | 高（代码+文件树+终端） | 高（节点+属性+日志） | 中→高（状态+进度+结果） |
| **导航模式** | 对话历史+搜索 | 文件树+对话+标签页 | 画布缩放+小地图+节点搜索 | 任务列表+状态面板 |
| **核心操作** | 发消息、引用上下文 | 发指令、审阅代码、批准执行 | 拖拽节点、配置参数、连线 | 定义目标、监控进度、干预/终止 |
| **状态可视化** | 打字指示器、流式输出 | 文件变更高亮、执行步骤列表 | 节点状态色（灰/蓝/绿/红） | 进度条、步骤时间线、成本计数 |
| **信任机制** | 引用来源、置信度 | 变更 Diff 预览、Plan 模式 | 节点输出预览、调试模式 | 沙盒预览、爆炸半径可视化 |
| **错误处理** | 重新生成、切换模型 | 自校正、回退到检查点 | 节点重试、分支回退 | 降级为人工审批、暂停恢复 |
| **反馈层级** | 对话气泡内嵌操作 | 行内 Diff + 侧栏详情 | 节点悬停 Tooltip + 侧栏 | 全局 Toast + 面板详情 |
| **自主权等级** | 低（一问一答） | 中（Plan→确认→Execute） | 中（用户编排+AI 执行节点） | 高（定义目标+Agent 自主规划执行） |

## AG-01~AG-10 完整规则

### AG-01：三档自主权模式（Suggest / Confirm / Execute）

> 规则来源：AI UX Playground — Suggest/Confirm/Execute 模式

Agent 界面必须支持三档自主权切换：
1. **建议模式**——仅输出方案，不执行任何操作
2. **确认模式**——每个关键操作前弹出审批面板
3. **执行模式**——自主运行，但保留暂停/终止入口

**默认模式**：首次使用=建议模式，建立信任后=确认模式，用户显式授权后=执行模式。

- **可执行规则**：界面必须有可见的当前模式标识，且切换入口不超过 2 次点击
- **检查方法**：在界面任意位置，能否在 2 次点击内切换自主权模式
- **适用场景**：所有 AI Agent 产品

---

### AG-02：过程透明——Agent 状态时间线

> 规则来源：Agentic Design — Agent Status & Activity UI Patterns (ASP)；WorkBuddy 右侧执行状态面板

Agent 执行多步骤任务时，必须展示**实时状态时间线**：已完成步骤✓ → 当前步骤（动画指示）→ 待执行步骤（灰色）。每个步骤至少展示：动作描述、目标对象、耗时。

不得仅在完成后一次性展示结果——用户需要"看着 Agent 干活"的安心感。

- **可执行规则**：执行时间 >5s 的任务必须有实时进度指示
- **检查方法**：触发一个多步任务，观察是否有实时更新的步骤时间线
- **适用场景**：AI 编程 Agent、AI 自主执行 Agent

---

### AG-03：Plan-then-Execute 分离

> 规则来源：Cursor Plan Mode；Agentic Design — Plan & Execute 模式

复杂任务（>3 步）必须先展示执行计划，用户确认后再开始执行。计划包含：步骤列表、每步影响范围、预估耗时/成本。

用户可以在计划阶段：
1. 删除步骤
2. 修改参数
3. 插入人工检查点
4. 取消执行

- **可执行规则**：任何涉及文件修改/外部 API 调用的任务，必须先展示计划
- **检查方法**：发起一个 5 步以上的任务，检查是否有计划展示和确认环节
- **适用场景**：AI 编程 Agent、AI 工作流编排

---

### AG-04：爆炸半径可视化

> 规则来源：AI UX Playground — Blast Radius Visualization + Reversibility Marking

高风险操作（删除文件、发送通知、支付、部署）执行前，必须展示**影响范围面板**：受影响的文件/数据/用户列表，用红色边框高亮。

不可逆操作必须：
1. 展示影响范围
2. 要求二次确认
3. 提供 30s 倒计时取消窗口

- **可执行规则**：任何 DELETE/PUT/POST 类操作必须有影响预览
- **检查方法**：触发一个删除操作，检查是否有受影响数据列表展示
- **适用场景**：所有 AI Agent 产品

---

### AG-05：错误恢复而非错误重置

> 规则来源：Agentic Design — Error Handling and Recovery Patterns (ERP)；AI UX Playground — Error Recovery Strategies

Agent 执行失败时，不得回到初始状态重头开始。必须提供：
1. 错误原因（用人类语言解释）
2. 可操作的修复建议
3. 从失败点恢复的入口
4. 完整的错误日志（可展开查看）

- **可执行规则**：错误发生后，用户应能在 2 次点击内恢复到最近的有效状态
- **检查方法**：模拟一个执行失败场景，检查是否有"从失败点恢复"入口
- **适用场景**：所有 AI Agent 产品

---

### AG-06：上下文窗口可视化

> 规则来源：AI UX Playground — Context Chip Management；Agentic Design — Context Window Management UI (CWM)

对话型 Agent 必须让用户感知上下文边界：
1. Token 使用量进度条
2. 已引用的文件/数据源列表（可展开/删除）
3. 长对话时的"上下文压缩"提醒

- **可执行规则**：用户必须能在 1 次点击内查看"Agent 当前知道什么"
- **检查方法**：对话 10 轮后，检查是否有上下文边界指示
- **适用场景**：AI 对话助手、AI 编程 Agent

---

### AG-07：渐进式披露推理过程

> 规则来源：Agentic Design — Progressive Disclosure UI Patterns (PDP)；Visual Reasoning Patterns (VRP)

Agent 的推理/决策过程默认折叠，只展示结论。用户可以逐层展开：
1. 结论
2. 关键推理步骤
3. 完整思考过程
4. 原始数据/日志

每层展开不超过 5 行摘要，避免信息轰炸。

- **可执行规则**：默认视图信息密度 ≤ 传统 B 端表格；展开后信息密度 ≤ IDE 调试面板
- **检查方法**：观察 Agent 输出，默认是否只显示结论
- **适用场景**：所有 AI Agent 产品

---

### AG-08：工作流编辑器的六要素

> 规则来源：Dify、n8n、LangFlow 的共同设计模式

节点式工作流编辑器必须包含：
1. **画布区**——自由拖拽节点和连线
2. **属性面板**——选中节点后右侧展示配置
3. **小地图/缩略图**——画布缩放>50%时自动出现
4. **调试模式**——逐步执行并高亮当前节点
5. **版本快照**——关键修改点可回溯
6. **节点搜索**——Cmd/Ctrl+K 快速定位

- **可执行规则**：工作流节点 >5 个时，必须有小地图和搜索
- **检查方法**：创建一个 10 节点的工作流，检查六要素是否齐全
- **适用场景**：AI 工作流编排（Coze/Dify/n8n 类产品）

---

### AG-09：Chat Artifacts 的双栏法则

> 规则来源：Claude Artifacts；AI UX Playground — Chat Artifacts 模式

当 Agent 生成的产物（代码/文档/图表/原型）超过对话气泡的合理展示范围时，必须使用**左右双栏**：左侧对话流 + 右侧产物预览。

产物预览区必须支持：
1. 独立滚动
2. 全屏切换
3. 复制/导出
4. 与对话上下文联动（点击对话中的引用跳转到产物对应位置）

- **可执行规则**：产物内容 >20 行代码 或 >300 字 或 含可交互元素时，必须双栏展示
- **检查方法**：让 Agent 生成一段 30 行代码，检查是否自动切换到双栏模式
- **适用场景**：AI 对话助手、AI 编程 Agent

---

### AG-10：Agent 任务队列与人工交接

> 规则来源：AI UX Playground — Task Queue + Human Handoff 模式

多任务并发时，必须展示**任务队列面板**：
1. 每个任务的状态（排队/执行中/等待审批/完成/失败）
2. 优先级标识
3. 预估剩余时间
4. 拖拽重排序

当 Agent 判断无法继续时，必须**主动交接**给人类，展示：
1. 已完成的步骤摘要
2. 卡住的环节及原因
3. 建议的人类操作

- **可执行规则**：用户必须能在 3 次点击内查看所有任务状态和交接信息
- **检查方法**：同时发起 3 个任务，检查是否有队列面板
- **适用场景**：AI 自主执行 Agent、多 Agent 协作

## NPL Agent 痛点专项分析

基于自然语言处理 Agent 的实际使用痛点，以下是界面设计中需要特别注意的问题：

| 痛点 | 根因 | 对应规则 | 修复优先级 |
|------|------|----------|:----------:|
| 用户不知道 Agent 在做什么 | 缺乏过程透明 | AG-02 | P0 |
| Agent 执行了错误操作 | 无确认机制 | AG-01 + AG-04 | P0 |
| 长对话后 Agent "遗忘" | 上下文边界不透明 | AG-06 | P1 |
| 失败后只能重来 | 无错误恢复 | AG-05 | P0 |
| Agent 思考过程太多 | 信息轰炸 | AG-07 | P1 |

---

## Agent Flow 痛点专项分析

基于工作流编排 Agent 的实际使用痛点：

| 痛点 | 根因 | 对应规则 | 修复优先级 |
|------|------|----------|:----------:|
| 节点多了找不到 | 缺乏小地图和搜索 | AG-08 | P0 |
| 工作流执行不知道卡在哪 | 节点状态不透明 | AG-02 + AG-08(调试模式) | P0 |
| 复杂工作流不敢执行 | 无爆炸半径预览 | AG-04 | P0 |
| 工作流修改后无法回退 | 无版本快照 | AG-08(版本快照) | P1 |
| 节点配置太复杂 | 属性面板不友好 | AG-08(属性面板) | P1 |
