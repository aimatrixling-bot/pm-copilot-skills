# 证据协议

## 证据优先于声明

AI Builder OS 不得在没有证据的情况下声称完成。

Iron Law：

```text
没有新鲜证据，不得声称完成、通过、修复或可发布。
```

如果没有在当前工作轮次中运行检查、读取结果或记录人工验证步骤，只能报告当前状态、未验证区域和下一步验证计划，不能把推断写成完成声明。

可接受的证据包括：

- 创建或修改的产物路径；
- 命令名称和关键输出；
- 测试、构建、lint、type check、eval；
- UI 工作中的截图或浏览器检查；
- 可重复的人工验证步骤；
- 明确列出的未验证风险。

## 完成声明等级

- `PASS`：对当前范围来说，必要检查已经运行或人工验证，且没有阻塞风险。
- `PARTIAL`：已有可用产出，但仍有范围或验证缺口。
- `BLOCKED`：缺少用户决策或外部状态变化，无法继续推进。

## 完成声明门禁

在写出“完成、已修复、可发布、测试通过、可以进入下一步”等声明前，必须完成：

1. 指出哪条命令、截图、diff、路径或人工步骤能证明该声明。
2. 运行或读取该证据，并确认结果与声明一致。
3. 明确列出没有覆盖的检查和仍需人类判断的区域。
4. 如果证据不足，使用 `PARTIAL`、`BLOCKED` 或“未验证”，不得用肯定语气掩盖缺口。

## 常见规避

| 规避说法 | 正确处理 |
| --- | --- |
| “应该能跑” | 运行最小验证，或标记未验证。 |
| “只是小改不用验” | 小改也要有 diff、路径或最小检查。 |
| “测试过一部分就够了” | 说明只覆盖了哪部分，不能声称整体通过。 |
| “agent 说成功了” | 独立读取产物、日志、diff 或测试输出。 |
| “截图看起来像真的” | 检查交互、状态、mock/demo 标注和证据来源。 |
