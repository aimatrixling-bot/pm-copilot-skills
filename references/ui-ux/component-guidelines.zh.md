# 组件一致性规范

组件规范的目标是让 agent 产出的页面、原型和实现保持一致、可复用、可审查。

## 组件选择顺序

1. 复用项目已有组件。
2. 复用已有 UI library 或 design system 的组件。
3. 组合基础组件。
4. 只有在确有必要时新增组件。

新增组件必须说明：

- 为什么已有组件不足。
- 新组件的使用场景。
- 变体和状态。
- 与现有样式的关系。

## 常见组件规则

- 按钮：区分 primary、secondary、danger、disabled；危险操作必须有明确文案或确认机制。
- 表单：必须覆盖必填、校验、错误、提交中、成功、失败状态。
- 表格/列表：必须覆盖空态、加载态、错误态、分页或长列表处理。
- 卡片：只用于重复项、摘要项或明确分组；不要用卡片堆叠页面结构。
- 导航：不能暗示不存在的路由或未实现功能已经可用。
- 弹窗/抽屉：必须说明打开条件、关闭方式、提交结果和失败处理。
- 状态徽标：必须有清晰语义，不只依赖颜色。

## 组件审计问题

- 是否复用了现有组件？
- 同类操作是否使用同类组件？
- 组件变体是否足够？
- disabled 和 loading 是否清楚？
- 错误和权限状态是否可见？
- 文案是否帮助用户理解业务，而不是只描述 UI？

## 禁止事项

- 不要每个页面临时创造一套按钮、卡片、表格样式。
- 不要用不可点击元素伪装可点击操作。
- 不要为了视觉丰富而牺牲信息密度和可扫描性。
- 不要把 fake data、fake navigation、fake action 写成真实能力。
