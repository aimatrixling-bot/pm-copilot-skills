# UI/UX 设计原则

AI Builder OS 的 UI/UX 契约服务于可构建、可评审、可验证的产品产物，不服务于装饰性展示。

## 基本原则

- 业务清晰优先于视觉炫技。
- 先确认用户、场景、任务和信息层级，再定义页面。
- 先复用现有组件和样式，再考虑新增模式。
- 状态完整性是设计质量的一部分，不是实现细节。
- 原型、spec、agent task、review 必须使用同一份 Design Brief 或明确说明偏离原因。
- Mock/demo 数据必须标注，不得伪装为真实生产数据。

## 信息层级

每个 UI 产物必须说明：

- 主用户是谁。
- 当前页面或流程帮助用户完成什么任务。
- 页面第一视口最重要的信息是什么。
- 次要信息如何组织。
- 哪些操作是主操作、次操作、危险操作。
- 哪些内容可以延后、折叠或移到详情页。

## 设计输入

进入 UI/UX 输出前，应尽量具备：

- Feature Frame 或 Builder Spec。
- 目标用户和核心场景。
- 主要任务流。
- 需要覆盖的状态。
- 现有产品、设计系统或组件约定。
- 验收和验证方式。

## 设计输出

UI/UX 输出至少应说明：

- 信息架构。
- 核心流程。
- 组件选择。
- 状态覆盖。
- 交互反馈。
- 响应式要求。
- 可访问性基础。
- 与既有视觉约定的关系。
- 未覆盖或暂时 mock 的部分。
